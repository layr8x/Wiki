# 마이클래스 챗봇 도입 효과: 2026년 6월 상담 빅데이터 심층 분석 (최종)

## 결정 요약

- **권고 결정: 1차 조건부 오픈(GO) · 2차 보류(설계 후 재상정).**
- **권고 ①** 1차 범위 = **조회 챗봇 + 계정·번호 매칭 수정을 함께** 오픈한다. 둘을 묶어야 카카오 빈번 문의의 약 50%를 대체한다. 조회 챗봇만 오픈하면 약 12%만 해결된다.
- **권고 ②** QA 경미 수정 5건 반영 + 수업 데이터가 있는 계정으로 재검수 1회 후 배포한다. 론칭을 막는 결함(블로커)은 0건이다.
- **권고 ③** 배포와 동시에 8장 측정체계를 가동한다. 50%·80%는 **예측치**이며, 배포 후 컨테인먼트(챗봇 내 해결 비율)로 **검증**한다.
- **조건부인 이유**: 카카오 최대 문제는 계정·번호 꼬임(약 39%)인데, 이는 챗봇 화면이 아니라 가입·접수 단계 수정으로만 해결된다. 따라서 1차 오픈의 조건은 "계정·번호 매칭 수정 병행"이다. 이 조건 없이 조회만 오픈하면 사용자의 가장 흔한 문제가 해결되지 않아 첫인상이 나빠질 위험이 있다(9장 리스크).
- **2차 보류 이유**: 신청·결제·취소 등 처리 기능은 미구현이며, 개발 공수가 크다(10장). 1차 효과를 측정한 뒤 근거를 가지고 재상정한다.

> **한 문장**: 챗봇은 컨설팅(전화 상담의 37.5%)을 대체할 수 없다. 가치는 카카오 디지털 채널 대체에 있으며, 1차(조회+계정 수정) 약 50%, 2차(+처리) 약 80%를 대체한다. 두 수치는 n=162 표본이라 ±5~8%p의 불확실성을 동반한다.

## 1. 오픈 단계별 대체 효과 (신뢰구간 포함)

> 카카오 162대화 전건 정독 분류 기준. 전화는 실장 기록 중분류 기준. **카카오 비율은 n=162 표본이라 Wilson 95% 신뢰구간을 함께 표기한다.**

### 1-1. 카카오 채널 - 단계별 누적 대체율 `[전수·분류 n=162]`

| 단계 | 대상 대화 | 누적 대체율 | 95% 신뢰구간 |
|---|---:|---:|---|
| 조회 챗봇(현재) | 19 | **11.7%** | 7.6 ~ 17.6% |
| **1차(조회 + 계정·번호 수정)** | 82 | **50.6% (≈50%)** | **43.0 ~ 58.2%** |
| **2차(+ 신청·처리 기능)** | 129 | **79.6% (≈80%)** | **72.8 ~ 85.1%** |
| 남은(사람 상담 + 노이즈) | 33 | 20.4% | - |

- **1차 오픈** = 조회 19대화 + 계정 63대화. 조회 해결 항목: 대기번호 · 재수강 확인 · 강의실 · 설명회/컨설팅 일정 · 출결 · 시간표 · 납부 조회. 계정 해결 항목: 계정 통합 · 학생/학부모 번호 매칭 · 로그인·연동 복구.
- **2차 오픈** = 위 50% + 처리 47대화(라이브·수강·전반·대기 신청, 취소·결제). 남은 약 20%는 사람 상담(환불 협의 등) → 요청 접수 후 1:1 답변.
- ★ 카카오 최대 문제는 **계정·번호 꼬임(약 39%)**이다. 조회 화면만으로는 1차에 약 12%만 줄고, **계정·번호 매칭 수정을 1차에 같이 해야 약 50%에 도달**한다.

### 5-4. 계정·번호 꼬임 약 39% - 어떤 현상인가 `[전수·분류·정성]`

**정의**: 한 학생을 둘러싼 전화번호와 앱 계정이 서로 어긋나, 앱이 본인(또는 자녀)의 수강·출결·결제 데이터를 보여주지 못하는 현상. 앱은 학생·학부모가 각자 따로 가입할 수 있는데, 둘을 잇는 번호 연결이 틀어지며 발생한다.

실제 카카오에 접수된 형태 5가지:

| # | 접수된 현상(고객 표현) | 무슨 상태인가 |
|---|---|---|
| 1 | "앱에서 자녀(제) 정보가 안 보여요" | 학부모 계정에 자녀 계정이 연결 안 됨 → 화면이 빈 상태 |
| 2 | "가입하려는데 '이미 등록된 번호'라고 떠요" | 그 번호가 이미 다른(중복·옛) 계정에 묶여 가입·연동 막힘 |
| 3 | "문자가 부모 번호로만 와요 / 번호 바꾸고 싶어요" | 알림 수신 번호가 한쪽만 등록, 앱에서 변경 막힘 |
| 4 | "계정이 2개로 되어 있어요, 합쳐주세요" | 한 사람이 계정 2개로 분리(통합회원 병합 필요) |
| 5 | "탈퇴/번호 삭제하려는데 안 돼요" | '이용 중인 서비스 있음' 등으로 계정 정리 막힘 |

> 1~3번은 모두 "앱이 사용자를 못 알아보는" 상태이다. 조회 챗봇은 "앱이 사용자를 알아본다"를 전제로 데이터를 보여주므로, 이 약 39%는 챗봇을 띄워도 보여줄 데이터가 없어 해결되지 않는다. **그래서 계정·번호 매칭 수정이 1차의 핵심 개선 과제이다.**

근본원인(5 Whys): ① 앱에서 내(자녀) 정보가 안 보임 → ② 학생 번호 미등록/오등록 → ③ 그 번호가 다른 계정에 묶여 "이미 등록된 번호" → ④ 학생·학부모가 각자 가입해 번호 엇갈림 → ⑤ 가입·접수 시 번호 매칭을 강제하지 않음.

## 6. 챗봇 준비도 (QA) `[측정·QA]`

2026-06-30 dev 환경 1차 검수 결과:

- **론칭 블로커 0건.** 조회 4메뉴(출결·보강 / 납부·결제 / 수업·시간표 / 전반) 핵심 플로우 모두 동작.

- 남은 경미 수정 5건(최다 = 빈 화면 만족도 노출 4곳) + 데이터 있는 계정 재검수 3건 → 수정 후 론칭 가능.

## 13. 한계와 메타인지

1. 전화 성공률은 추정(챗봇 미배포) - 실제값은 배포 후 측정한다. 카카오 대체율은 전수 정독 분류이나 표본 162라 신뢰구간을 동반한다(분류 판단 ±, 보수적으로 분류).
2. 카카오 n=162 소표본 - 순위·구조 파악용이며 비율은 ±5~7%p 폭을 가진다. 단일 채널(앱 기술지원이라 계정 문제가 과대대표될 수 있음).
3. 단일 지점(대치단과)·1개월. 상담 원문(PII)은 반입하지 않고 집계만 남긴다.
4. AMS와 카카오는 확실성 등급이 다르다(전수 vs 표본). 두 채널 수치를 같은 확신으로 다루지 않는다.

**다음 단계**: ① 1차 = 조회 챗봇 + 계정·번호 매칭 수정으로 조건부 오픈(카카오 약 50%) ② QA 경미 5건 수정 + 재검수 ③ 8장 측정체계 가동 ④ 2차 = 신청·처리 기능 설계 후 재상정(카카오 약 80%).

## 별첨. 용어집

| 용어 | 풀이 |
|---|---|
| AMS | 학원 운영 시스템. 실장이 전화·방문 상담을 기록하는 원장(原帳) |
| 1차/2차 | 1차=내 정보 조회(구현 완료), 2차=신청·변경 처리(미구현) |
| 컨테인먼트 | 챗봇이 사람에게 넘기지 않고 챗봇 안에서 끝낸 비율 |
| MoM | 직전 달 동일 기준 대비 증감 |
| 전수·분류 | 162대화를 한 건씩 읽어 성격을 분류한 사실 |
| 표본 / 전수 | 표본=일부(카카오 162)·오차 동반 / 전수=전부(AMS 81,863)·오차 없음 |
| Wilson 95% 신뢰구간 | 표본 비율의 참값이 95% 확률로 들어갈 범위(소표본에 적합한 계산법) |
| 민감도 분석 | 가정(예: 계정 수정 효과)을 바꿔가며 결과가 얼마나 움직이는지 보는 것 |
| 이중차분(DiD) | 처치군과 대조군의 전후 변화 차이로 순수 효과를 분리하는 인과추론법 |
| North Star | 제품 성공을 대표하는 단일 핵심지표 |
| RICE | Reach·Impact·Confidence·Effort로 과제 우선순위를 매기는 방법 |
| LLM | 대형언어모델. 자연어 입력으로 추천·요약하는 AI |
| 업무 이전 | 반복 업무를 도구로 옮겨 사람이 고부가 업무에 집중하게 하는 것 |

*카카오 = 162대화 전건 정독 분류(Wilson 95% CI 동반). 전화 = openpyxl·pandas 2중 검증 전수. 모든 핵심 수치는 원본 CSV에서 독립 재집계로 교차검증(불일치 0건). - 2026-06.*
