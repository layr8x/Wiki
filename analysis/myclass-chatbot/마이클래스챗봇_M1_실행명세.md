# M1 실행 명세 — 오픈/파일럿 전 준비 (~2주)

> **결론 (두괄식)** — M1은 챗봇을 **"측정 가능하고 흠 없는 상태"** 로 만드는 2주 작업이다. 워크스트림 4개 — **A. 컨테인먼트 계측 이벤트** · **B. 조회화면 4종 보강** · **C. QA 경미 5건 수정+재검수 3건** · **D. Before 고정**(본 문서에서 분석 완료). **A·B·C는 개발팀, D는 분석.** ★ **파일럿 진행 여부와 무관하게 M1은 진행 가치가 있다** — B·C는 어떤 론칭에도 필요하고, A(계측)는 오픈 후 상시 컨테인먼트 모니터링에 그대로 쓰인다. D(Before)는 지금 못 박지 않으면 나중에 "원래 그 정도였다"를 반박 못 한다.

|---|---|
| **상태** | M1 착수 **승인됨** / 파일럿 진행 여부 미정 |

## 1. WS-A — 컨테인먼트 계측 이벤트 (개발) ★ 게이트 측정의 심장

> 컨테인먼트(=사람 안 거치고 챗봇에서 끝난 비율)는 **핸드오프 이벤트가 없으면 분자를 못 잡아** 측정 자체가 불가하다. 그래서 최우선.

**발화할 이벤트(최소 세트):**

| 이벤트 | 시점 | 핵심 필드 |
|---|---|---|
| `session_start` | 챗봇 진입 | session_id, user_type(학생/학부모), 지점 |
| `menu_enter` | 메뉴 선택 | session_id, menu_code(출결보강·납부결제·수업시간표·전반), **intent_class(조회/처리)** |
| `lookup_render` | 조회 결과 표출 | session_id, screen, has_data(bool) |
| `handoff_click` | **[상담 연결] 클릭** | session_id, from_screen | 
| `session_end` | 종료 | session_id, reason(만족도해결/닫기/이탈), satisfied(👍/👎/none) |

**산식(대시보드에 고정):**
```
조회 인텐트 세션 = menu_enter(intent_class='조회')의 distinct session
핸드오프 세션   = 위 중 handoff_click 발생 세션
컨테인먼트율    = 1 − 핸드오프 세션 / 조회 인텐트 세션
(보조지표) 만족도 해결 종료율 = session_end(satisfied=👍) / 조회 인텐트 세션
```

> **차선책(이벤트 구현 지연 시, 개발비 0)**: 챗봇→외부 화면(납부/결제) 딥링크에 `?src=chatbot_{menu}` 를 박아 **위키·AMS 유입 출처**로 사용량을 간접 측정. 단 컨테인먼트(핸드오프) 분자는 못 잡으므로 **게이트 측정엔 정식 이벤트가 필요**.

## 2. WS-B — 조회화면 4종 보강 (기획+개발)

> 현재 "조회형"인데 화면이 없거나 미흡해 못 푸는 문의. **이 4종이 조회 컨테인먼트를 69%→80%선으로 올리는 핵심 갭**(§측정설계). 6월 모수는 전화 기준.

| 화면 | 6월 모수 | 현재 | 보여줄 데이터 | 빈 상태 | 하단 버튼 |
|---|---:|---:|---|---|---|
| **대기 번호 확인** | 1,335 | cur 5 | 대기 강좌 · 내 대기번호 · 예상 충원 순번 | "대기 중인 강좌가 없어요" | 이전·처음으로 |
| **재수강 확인** | 360 | cur 45 | 입반된 강좌의 재수강 여부·회차(= '입반 강좌 확인' 확장) | — | 이전·처음으로 |
| **설명회·컨설팅 일정** | 287 | cur ~9 | 다가오는 설명회·컨설팅 **일정 조회**(예약·변경은 2차 → 상담 연결) | "예정된 일정이 없어요" | 상담 연결·이전·처음으로 |

- 합계 모수 **2,153건/월**. 모두 **조회 전용**(처리 아님)이라 1차 범위 유지.

## 3. WS-C — QA 경미 5건 수정 + 재검수 3건

> 6/30 QA 결과 **론칭 블로커 0**, 아래는 경미·중 수정. 1·4·5는 **프로토타입(설계 정본)이 이미 올바르므로 프로토타입 기준으로 맞추면 됨**.

| # | 항목 | 구분 | 담당 |
|---|---|---|---|
| 1 | **빈 화면 만족도 미노출** — 오늘 수업없음·타반보강 없음·추가영상 없음·결제내역 없음 4곳 | 콘텐츠·로직 | 기획·프론트 |
| 2 | **전체 회차** — "전체 N회 중 M회차 진행 중" 문구 추가 + 회차 정렬·15회차 중복 점검 | 콘텐츠+데이터 | 기획·개발 |
| 3 | **내 시간표 수업시간 빈칸**("월 /") — 시간 표기 누락 | 데이터·레이아웃 | 개발 |
| 4 | **전반 첫 안내문** "어떤 강좌로 전반을 원하시나요?" → 자연스러운 표현 | 콘텐츠 | 기획 |
| 5 | **납부기한 표기 통일** — 챗봇 12/26 ↔ 결제 25.12.26 | 콘텐츠 | 프론트 |

**재검수 3건** (6/30엔 데이터 부재로 미확인 → **수업 있는 계정/날짜로 1회 추가 검수**): 오늘 출석 '있음' 출결상태 표기 · 타반보강 '일정 있음' 형식 · 동영상보강 시청기한·N분 형식.

## 5. 완료 기준 (DoD) — "측정 가능 상태" 체크리스트

- [ ] 모든 화면에서 `handoff_click`·`menu_enter(intent_class)` 이벤트가 실제로 쌓인다 (WS-A)
- [ ] 컨테인먼트 산식이 대시보드에서 계산된다 (WS-A)
- [ ] 조회화면 4종이 데이터 있는 계정에서 동작한다 (WS-B)
- [ ] QA 경미 5건 ✓ + 재검수 3건 통과 (WS-C)
- [ ] Before 표가 동결돼 변경 이력이 잠겼다 (WS-D, **완료**)

→ 5개가 모두 ✓ 되면 챗봇은 **"오픈해도, 파일럿해도 측정되는 상태"** 가 된다.

## 6. 파일럿 미정 시 — 대안 측정 경로 (M1은 그래도 진행)

파일럿 여부는 미정이지만, **M1은 어느 경로에서도 필요**하다:

| 경로 | 80% 게이트 측정 방법 | M1 필요분 |
|---|---|---|
| **(가) 파일럿** | 일부 세그먼트 노출 → 마지막 2주 컨테인먼트 실측 + 이중차분 | A·B·C·D 전부 |
| **(나) 단계적 오픈**(staged rollout) | 전체에 점진 노출하며 **프로덕션 컨테인먼트**를 주간 모니터링, 80% 도달 확인 | A·B·C·D 전부(대조군만 토픽 대조로 대체) |
| (다) 직접 오픈 | 오픈 후 컨테인먼트 상시 모니터링(게이트 사후 확인) | A·B·C 필수 |

> 즉 **계측(A)·화면 보강(B)·QA 수정(C)** 은 파일럿 결정과 독립적으로 진행하면 된다. 파일럿 결정이 영향을 주는 건 **"측정 모집단을 어떻게 나누느냐(세그먼트 대조군 vs 점진 노출)"** 뿐이다. → **M1 착수에 파일럿 결정을 기다릴 필요 없음.**

## 별첨. 이벤트 스키마 예시 (개발 참고)

```json
{ "event": "menu_enter", "session_id": "s_...", "user_type": "학부모",
  "menu_code": "attend_makeup", "intent_class": "조회", "ts": "..." }
{ "event": "handoff_click", "session_id": "s_...", "from_screen": "makeup_none", "ts": "..." }
{ "event": "session_end", "session_id": "s_...", "reason": "satisfied", "satisfied": "up", "ts": "..." }
```
컨테인먼트 = `1 − COUNT(DISTINCT handoff 세션) / COUNT(DISTINCT 조회인텐트 세션)`.
