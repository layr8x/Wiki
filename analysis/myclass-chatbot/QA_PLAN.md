# 마이클래스 인앱 챗봇 — 품질 기준 · 테스트 플랜 (QA Plan)

> **목적**: 이 문서는 같은 폴더의 `prototype.html`(인터랙티브 프로토타입, **SSOT**)을 **그대로 들고 검증**하는 실행 체크리스트다.
> **근거 문서**: `prototype.html`(SSOT) · `SCENARIO_PLAN.md` · `UX_COPY.md`(최종 카피) · `RESOLUTION_EVIDENCE.md`(가이드 근거).
> **테스트 대상**: 빠른 메뉴 8타일 + '자주 찾는 것' 칩 + 3채널 상담 핸드오프(전화·마이클래스 카톡·LIVE 카톡).
> **작성 관점**: 시니어 QA — 모든 케이스는 "누가 봐도 같은 결과가 나오도록" 사전조건·단계·기대결과를 명시한다.

> **중요 전제**: 챗봇은 **이미 로그인된 마이클래스 앱 내부**에서 동작한다. 별도 온보딩·본인확인(2필드 입력) 게이트는 **없다**. 모든 조회는 로그인된 김시대(대치 캠퍼스) 컨텍스트로 바로 이뤄진다.

## 0. 문서 사용법 (테스터 가이드)

| 표기 | 뜻 |
|---|---|
| **Tier** | T1 즉답(가이드) / T2 개인화 조회(로그인 컨텍스트) / T3 상담 핸드오프 |
| **라우팅** | auto(바로 분기) / disamb(되묻기) / human(사람·채널) |
| **PASS 조건** | 기대결과가 화면에 그대로 나타나고, 카드 하단에 다음 행동이 1개 이상 존재 |
| **FAIL 조건** | 막다른 길 발생 / 의도치 않은 개인정보 노출 / 카피 불일치 / JS 콘솔 에러 |
| **P0~P3** | 심각도. P0=출시 차단, P1=출시 전 필수, P2=출시 후 빠른 수정, P3=개선 |

테스트 환경(반드시 이 위에서 실행):
- **3뷰 전환기(viewswitch)**: 화면 상단 토글로 **모바일 / 태블릿 / 데스크탑** 전환. 모든 핵심 플로우는 3뷰 모두에서 통과해야 한다.
  - 모바일: 바텀시트(90% 높이) · 드래그 핸들로 닫기.
  - 태블릿·데스크탑: 우하단 **도킹 패널 392×700**(화면 넘으면 자동 축소) · 닫기 버튼으로 닫기.
- 기기: 모바일 우선(데이터상 모바일+태블릿 95.8%). iPhone Safari · Android Chrome.
- 화면폭: 360px(최소) · 390px · 414px · 430px(최대).
- 네트워크: 정상 / 느린 3G / 오프라인(엣지케이스용).
