# 마이클래스 인앱 챗봇 — 품질 기준 · 테스트 플랜 (QA Plan)

> **목적**: 이 문서는 같은 폴더의 `prototype.html`(인터랙티브 프로토타입)이 완성되면 **그대로 들고 검증**하는 실행 체크리스트다.
> **근거 문서**: `QUICK_MENU_SCENARIOS.md`(v3 디지털 우선) · `DATA_ANALYSIS.md`(3소스 교차검증) · `UX_COPY.md`(최종 카피).
> **테스트 대상**: 빠른 메뉴 8타일 + 온보딩 + 상담원 핸드오프 + 능동 알림 N1~N9.
> **작성 관점**: 시니어 QA — 모든 케이스는 "누가 봐도 같은 결과가 나오도록" 사전조건·단계·기대결과를 명시한다.

## 0. 문서 사용법 (테스터 가이드)

| 표기 | 뜻 |
|---|---|
| **Tier** | T1 즉답(가이드) / T2 개인화 조회(본인확인 필요) / T3 상담원 핸드오프 |
| **라우팅** | auto(바로 분기) / disamb(되묻기) / human(사람) |
| **PASS 조건** | 기대결과가 화면에 그대로 나타나고, 카드 하단에 다음 행동이 1개 이상 존재 |
| **FAIL 조건** | 막다른 길 발생 / 개인정보 노출 / 카피 불일치 / 본인확인 우회 위반 |
| **P0~P3** | 심각도. P0=출시 차단, P1=출시 전 필수, P2=출시 후 빠른 수정, P3=개선 |

테스트 환경(반드시 이 위에서 실행):
- 기기: 모바일 우선(데이터상 모바일+태블릿 95.8%). iPhone Safari · Android Chrome.
- 화면폭: 360px(최소) · 390px · 414px · 430px(최대).
- 네트워크: 정상 / 느린 3G / 오프라인(엣지케이스용).
