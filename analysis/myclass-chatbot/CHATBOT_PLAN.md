## 0. v6 4메뉴 구조 (SERP-8270)

v6에서 옛 8메뉴(계정·로그인·앱 / 미납·결제·환불 / 입반·등록·대기 / 라이브·교재·배송 / 출결·보강 / 수업·시간표 / 퇴원·전반 / 상담원·자주묻는것)는 **4메뉴로 축소**된다.

| # | 메뉴 | 노드 | 옛 8메뉴 대비 |
|---|---|---|---|
| 1 | **출결·보강** (attend) | 오늘 출석 확인 · 강좌 선택→[동영상 보강/타반보강/추가영상] · **입반 강좌 확인** · 강좌 선택 | 옛 '입반·등록·대기'의 입반 확인이 여기로 흡수 |
| 2 | **납부·결제** (pay) | 납부 현황(납부필요 / 납부대기·가상계좌 2섹션) · 결제 내역(결제완료·부분환불 + 외 N건) | 옛 '미납·결제·환불' 축소 |
| 3 | **수업·시간표** (time) | 내 시간표 · 강좌별 전체 회차 일정 · 종강일 확인 | 유지·확장 |
| 4 | **전반** (overall) | 전반 가능한 강좌 확인하기 (옛 '시간이 안 맞아요', 타시간=지점단과별 노출) | 옛 '퇴원·전반'의 전반 대안만 남김 |

- **삭제된 메뉴**: 계정·로그인·앱 / 라이브·교재·배송 / 퇴원 / 상담원·자주묻는것 / 입반·등록·대기(별도 메뉴로는 없음, 입반 확인만 출결·보강으로 이동).
- **공통 UX(SERP-8270, 모든 화면)**: ①2Depth 이상 = **[이전]+[처음으로] 둘 다** ②헤더 **[홈] 버튼 삭제**(우상단 닫기 X만) ③**[상담 등록] 제거 → 상담 연결(전화)만**, 클릭 시 **지점별 전화번호** 노출 ④아이콘 = Material Symbols Rounded weight 300.
- 노드별 답변 포맷·하단 버튼 상세는 **`기획서_v6_요약.md 3장`**가 정본. 본 문서는 근거·플로우 요약.

## 3. 정보구조 (IA) - v6 4메뉴 트리

> 로그인된 앱 세션에서 챗봇 오픈 → 별도 본인확인 게이트 없이 개인화 첫 인사. 홈 = **4타일 그리드**.
> 노드별 답변 포맷·하단 버튼의 정본은 `기획서_v6_요약.md 3장`. 아래는 흐름 골격.

```

홈 (4 타일)
├─ ① 📋 출결·보강 (attend)
│   ├─ 오늘 출석 확인 ▸ "오늘(M/D) 출석 현황" + 강좌별 수업시간/출결(출석 QR시각 / 출석예정 / 수업없음) · [이전][처음으로]
│   ├─ 강좌 선택 ▸ "어떤 강좌를 확인할까요?" + 강좌칩(입반 완료만 노출) → 강좌 선택 후:
│   │     ├─ 동영상 보강 ▸ 회차명·마이클래스(VOD)·시청 기한·시청시간(제공/시청) (변형: 영상 준비 중 / 연구실 동영상 / 출석 처리됨) · 없음 고정문구

│   │     └─ 추가영상 ▸ 회차명·지급일·시청 기한·상태 · 없음 고정문구

├─ ② 💳 납부·결제 (pay)
│   ├─ 납부 현황 ▸ "%강좌명% 납부 현황" + [납부필요] 섹션 + [납부대기 or 가상계좌 입금 대기] 섹션(수강료·교재비·합계·납부기한) · [납부하기][이전][처음으로] · 전체완납 → 고정문구
│   └─ 결제 내역 ▸ "최근 3개월 결제 내역" + 결제일·강좌명(외 N건)·금액·수단(카드사)·상태(결제완료 / 부분환불) · 없음 "결제 내역이 없어요." · [이전][처음으로]
├─ ③ 📅 수업·시간표 (time)
│   ├─ 내 시간표 ▸ "이번 주(M/D~M/D) 시간표" + 요일·시각·강좌명·강의실(요일순) · [다음 주 보기][이전][처음으로]
│   ├─ 강좌별 전체 회차 일정 ▸ 강좌 선택 → "%강좌명% 전체 일정" + 회차·날짜(요일)·시각 + "전체 N회 중 M회차 진행 중" · [다른 강좌 보기][이전][처음으로]
│   └─ 종강일 확인 ▸ "강좌별 종강일" + 강좌명→YYYY-MM-DD + "휴강·일정 변경은 상담실로" · [상담 연결][이전][처음으로]

만족도: 데이터 조회/자가안내 완료 종료 화면 = [👍 해결됐어요][👎 아직 안 됐어요]. 빈 상태·순수 상담/전화 종료·진입/선택 화면은 미노출.
```

### 4.1 진입 & 첫 인사 (게이트 없음)
```
챗봇 오픈(로그인 앱 세션) → 봇: "안녕하세요, 김시대님. 대치 캠퍼스 기준으로 안내해 드릴게요. 무엇을 도와드릴까요?"
→ 4타일 그리드(출결·보강 / 납부·결제 / 수업·시간표 / 전반)
근거: 챗봇은 로그인된 앱 안에서 열려 학생·지점을 세션에서 받음 → 별도 본인확인 게이트 불필요.
학부모용: 자녀 4명 전환(김시대·대치·고3 / 이시대·목동·고2 / 박시대·반포·고1 / 최시대·분당·중3), 인사말 "학부모님 / {학생} 학생({지점}) 기준".
```

### 4.2 ① 출결·보강 (전화 1위 30.7% + 입반 확인 흡수)
```
[출결·보강] → 봇:"출결·보강, 무엇을 확인할까요?"
[오늘 출석 확인] [강좌 선택(보강)] [입반 강좌 확인]

[오늘 출석 확인] → <Card: "오늘(M/D) 출석 현황이에요." + %강좌명% + 수업 %시작%~%종료% / 출석 %QR태그시각%>
     출석 전 → "출석예정" · 수업 없음 → 고정문구. 버튼 [이전][처음으로] · 만족도 노출
[강좌 선택] → 봇:"어떤 강좌를 확인할까요?" + 강좌칩 (*입반 완료된 강좌만 노출, 입반 예정 제외)
     강좌 없음 → "현재 입반 중인 강좌가 없어요." 버튼 [강좌 선택 버튼][이전][처음으로]
  → 강좌 선택 후 → 봇:"어떤 내용을 확인할까요?" [동영상 보강][타반보강][추가영상] (항상 3개 고정)
     [동영상 보강] → <Card: %회차명% | 마이클래스(VOD) | 시청 기한 %시청기한% | %총시청%분 제공 (%시청완료%분 시청)>
          변형: "영상 준비 중" / "연구실 동영상 | 연구실 문의" / "출석 처리됨". 없음 → 고정문구. 만족도 노출(빈 상태 제외)
     [타반보강] → <Card: "%강좌명% 타반보강 가능 일정이에요." + %회차명% | %날짜%(%요일%) | %시작%~%종료% | %강의실%>
          없음 → "…없어요. 문의는 상담 연결 버튼으로" 버튼 [상담 연결][이전][처음으로] (빈 상태 = 만족도 미노출)
     [추가영상] → <Card: %회차명% | 지급일 %지급일% | 시청 기한 %시청기한% %상태%> 없음 → 고정문구
[입반 강좌 확인] → <Card: "입반된 강좌 현황이에요." + %강좌명%(완납=결제버튼 없음·카드 반복)>
     없음 → "현재 입반된 강좌가 없어요." 버튼 [이전][처음으로]
```

### 4.3 ② 납부·결제 (실사용자 결제완료 ~80% · 톤 = 도와주기)
```
[납부·결제] → 봇:"납부·결제, 무엇을 도와드릴까요?"
[납부 현황] [결제 내역]

[납부 현황] → <Card: "%강좌명% 납부 현황이에요."
     [납부필요] 섹션: 수강료 %회차%회 %금액%원 / 교재비 %교재명% %금액%원 / 합계 %합계%원 / 납부기한 %기한%
     [납부대기 or 가상계좌 입금 대기] 섹션: 동일 구조>
     버튼 [납부하기][이전][처음으로] · 만족도 노출. 전체완납 → "모든 수강료가 납부 완료됐어요."
[결제 내역] → <Card: "최근 3개월 결제 내역이에요." + %결제일% | %강좌명% (외 N건) | %금액%원 | %수단%(%카드사%) | %상태%>
     상태 = "결제완료" / "부분환불(환불금액: %금액%원)". 없음 → "결제 내역이 없어요." 버튼 [이전][처음으로](빈 상태 = 만족도 미노출)
```

### 4.4 ③ 수업·시간표 (조회)
```
[수업·시간표] → 봇:"수업·시간표, 무엇을 볼까요?"
[내 시간표] [강좌별 전체 회차 일정] [종강일 확인]

[내 시간표] → <Card: "이번 주(M/D~M/D) 시간표예요." + %요일% %시작%~%종료% %강좌명% · %강의실%(요일순)>
     없음 → 고정문구. 버튼 [다음 주 보기][이전][처음으로] · 만족도 노출
[강좌별 전체 회차 일정] → 강좌 선택 → <Card: "%강좌명% 전체 일정이에요." + %회차명% | %날짜%(%요일%) | %시작%~%종료% + "전체 N회 중 M회차 진행 중">
     버튼 [다른 강좌 보기][이전][처음으로] · 없음 → "회차 일정 정보를 불러올 수 없어요." · 만족도 노출
[종강일 확인] → <Card: "강좌별 종강일이에요." + %강좌명% → YYYY-MM-DD + "휴강·일정 변경은 상담실로…">
     버튼 [상담 연결][이전][처음으로] · 만족도 노출(데이터 조회 종료 화면)
```

### 4.5 ④ 전반 (전반 가능한 강좌 확인하기 - 옛 '시간이 안 맞아요')
```
[전반] → 강좌 선택(%강좌명% %요일% %시각% %정원/잔여%)
  → <Card: "%강좌명%의 다른 시간대 강좌예요." + %지점단과% - %강좌명% %요일% %시각%(여러 지점) + "반 변경 신청은 상담을 통해…">
  없음 → "현재 %강사명% 선생님의 다른 시간대 강좌가 없어요…"
  버튼 [상담 연결][이전][처음으로] · 전반결과(데이터 분기) = 만족도 노출, 없음(빈 상태) = 미노출
```

### 4.6 공통 (상담 연결·만족도·종료)
```
상담 연결(handoff): [상담 연결] 클릭 → 지점별 전화번호 노출(예: 대치 캠퍼스 02-552-2373). 상담 등록/문자 접수 없음(전화 연결만).
종료·만족도: 데이터 조회·자가안내 완료 화면 → "도움이 됐나요?" + [👍 해결됐어요][👎 아직 안 됐어요]
  · 미노출 = 빈 상태(내역 없음)·순수 상담/전화 종료·진입/선택 화면
컴플레인(민감): 추측 응답 금지 → 즉시 상담 연결
```

## 5. 노드별 콘텐츠 패턴 (봇 발화·데이터 스키마·액션)

| 카드 | 구성 | 데이터(API) | 액션 |
|---|---|---|---|
| **오늘 출석 카드** | 강좌별 수업시간 + 출결(출석 QR시각 / 출석예정 / 수업없음) | 출결 DB | [이전][처음으로] |
| **동영상 보강 카드** | 회차명·마이클래스(VOD)·시청 기한·시청시간(제공/시청) + 변형(영상 준비 중/연구실 동영상/출석 처리됨) | 학사/LMS API | 없음 고정문구 |
| **타반보강 카드** | 회차·날짜(요일)·시각·강의실 | 보강 조회 API | 없음 → [상담 연결] |
| **추가영상 카드** | 회차명·지급일·시청 기한·상태 | 학사/LMS API | 없음 고정문구 |
| **입반 강좌 확인 카드** | 강좌명 목록(완납=결제버튼 없음·카드 반복) | 수강 DB | [이전][처음으로] |
| **납부 현황 카드** | [납부필요] + [납부대기·가상계좌] 2섹션(수강료·교재비·합계·납부기한) | 수납 DB | [납부하기] |
| **결제 내역 카드** | 결제일·강좌명(외 N건)·금액·수단(카드사)·상태(결제완료/부분환불) | 수납 DB | [이전][처음으로] |
| **내 시간표 카드** | 요일·시각·강좌명·강의실(요일순) + 이번주/다음주 | 시간표 DB | [다음 주 보기] |
| **전체 회차 일정 카드** | 회차·날짜(요일)·시각 + "전체 N회 중 M회차 진행 중" | 학사 API | [다른 강좌 보기] |
| **종강일 카드** | 강좌별 종강일 YYYY-MM-DD + 휴강 고지 | 학사 API | [상담 연결] |
| **전반(다른 시간대) 카드** | 지점단과별 강좌(요일·시각) + "반 변경은 상담" | 강좌 정원·시간표 API | [상담 연결] |

문체 규칙: -요체, 따뜻하되 간결. 버튼은 "사용자가 얻는 것"(납부하기/다음 주 보기/다른 강좌 보기). 단정 금지 항목은 "[확인필요]". 사람 호칭 = "상담 선생님", 연결 = "상담 연결(전화, 지점별 번호)". 강좌명 축약 금지·실명 유지, 날짜 정본 YYYY-MM-DD(화면 표기는 결제/종강 등 맥락별).

## 6. 라우팅·사람 연결·운영 규칙

- **분류 신뢰도(분류기 F1, 5-fold CV)**: F1≥0.80(출결·정산 등) = auto / 혼동쌍 = 1-step 명확화 / 컴플레인(F1 0.39) = 즉시 상담 연결.
- **개인 데이터 조회(T2)**: 로그인 앱 세션의 학생·지점 전제. 세션 정보로 본인 데이터만 조회.
- **사람 연결 = 상담 연결(전화) 하나**(SERP-8270): [상담 연결] 클릭 시 지점별 전화번호 노출. 옛 3채널(상담실 전화·마이클래스 카톡·LIVE 카톡)은 v3 설계 기록으로 폐기, v6는 전화 상담으로 단순화.
- **운영시간**: 평일 사람 응대. 늦은 시간엔 즉답·조회는 가능, 사람 연결은 운영 시작 시 응대.
- **개인정보**: 조회는 로그인 본인 데이터만. 등록 연락처·송장은 마스킹, 본인 전용 정보는 노출+복사. 미성년 데이터 - 법정대리인 동의(개발 [확인필요]).

## 7. 데이터 의존성 (개발 연계)

| 기능 | 필요 데이터/API |
|---|---|
| 출결 조회 | 출결 DB(출석/결석/QR 태그시각/출석예정) |
| 보강(동영상·타반·추가영상) | 학사/LMS 보강 조회 API(회차·시청권·시청진도·타반 일정) |
| 입반 강좌 확인 | 수강 DB(입반 완료 강좌) |
| 납부·결제 | 수납 DB(납부필요·납부대기·가상계좌·결제 내역·부분환불) |
| 시간표·전체 회차·종강일 | 시간표/학사 DB(요일·강좌·강의실·회차·종강일) |
| 전반(다른 시간대) | 강좌 정원·시간표 API(지점단과별 강좌) |
| 개인화 | 로그인 앱 세션의 학생·지점 전달 |
| 사람 연결 | 지점별 상담 전화번호 |

> blocker(현재): 보강 조회 API·전반 지점단과 조회 등 백엔드 미연결. 조회 카드 데이터 전부 목업.
