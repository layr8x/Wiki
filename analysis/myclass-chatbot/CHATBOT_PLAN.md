## 4. 대화 플로우 (케이스별 상세 — 노드·분기·콘텐츠·핸드오프)

표기: `봇:` 발화 · `[칩]` 빠른답변 · `<Card>` 카드 · `→` 분기.

### 4.1 온보딩
```
스플래시(1.7s) → 봇: "안녕하세요! 안전한 상담을 위해 학생 정보를 확인할게요."
[본인확인] 학생 이름 + 학부모 연락처 뒷 4자리
  → 일치: 봇: "{학생}님 반가워요 😊" → 메인 8타일
  → 불일치(2회): "확인이 어려우면 상담원이 도와드릴게요" → 상담원
근거 L: 폼 최소화하되 본인확인은 유지(개인 데이터 조회 전제). GA4 모바일 95.8% → 입력 2필드로 제한.
```

### 4.2 ① 수업·출결 (최대 볼륨 30.7%)
```
[수업·출결] → 봇:"무엇을 확인할까요?"
  [오늘 출석 확인] → <DataCard 출결: 출석 11 · 결석(보강필요) 1 · 지각 0> [동영상 보강][처음으로]
  [동영상 보강] → <Guide: ①결석 반영 확인 ②앱>출결>동보 신청 ③다음날 9시 오픈·7일>
                  + <Data 남은 보강 N회 · 신청 시 차감 안내> [보강 신청하기][상담]
  [결석·지각 예정 신고] → 봇:"날짜·수업을 입력해 주세요" [Input] → "접수됐어요. 담임선생님 확인 후 처리"
  [동보 자료 받기] → <Guide 앱>수업자료 경로 · 업로드 시점>
  [현장 보강] → <Guide: 마감반 5분전 입실 · 결석생 없으면 입실 불가 가능>
핸드오프 조건: 정책 예외·분쟁 → 상담원(맥락칩: 학생·강좌·문의유형).
```

### 4.3 ② 수강료·납부 (결제 이탈 61% 대응)
```
[수강료·납부] → 
  [미납·납부 현황] → <DataCard: 미납 합계·강좌별 상태·교재비> 
        주행동 [지금 결제하기] (결제페이지 딥링크) · 보조 [결제 문자 다시 받기]
        ※ GA4 /inbound/payment 진입 시 이 카드 **능동 배너**로 선노출
  [수강료·교재비 문의] → <DataCard 청구 내역>
  [가상계좌] → <DataCard 은행·계좌(마스킹)·금액·기한> [계좌 복사]
```

## 5. 노드별 콘텐츠 패턴 (봇 발화·데이터 스키마·액션)

| 카드 | 구성 | 데이터(API) | 액션 |
|---|---|---|---|
| **GuideCard** | 제목 + 번호 단계(1~4) + 비고 + 딥링크 | 정적 콘텐츠(KB) | 딥링크 / "도움이 됐나요?" |
| **DataCard** | 헤더(라벨+학생태그) + key·value 행(상태 색+텍스트) + 주행동 | 출결·수납·수강·대기 DB | 결제·신청·복사 |
| **AltCard(전반/대안)** | 현재 강좌 + 대안 N + 잔여석 | 강좌 정원 API | 전반 신청 |
| **TimetableCard** | 강사(마스킹)·요일/시간 칩·수업일 | 시간표 DB | 입반 신청 |
| **RefundCard** | 시작일·이용회차·예상환불 + 규정 고지 | 환불 계산 | 상담원 |
| **HandoffCard** | 전달내용(최소식별) + 동의 + 접수번호 + 연결 후 안내 | 티켓 발급 | 연결/수정 |
| **ContactCard** | 부서별 전화(마스킹) | 정적 | tel: |
| **Input** | placeholder + 접수 | 접수 큐 | 전송 |

문체 규칙: –요체, 따뜻하되 간결. 버튼은 "사용자가 얻는 것"(지금 결제하기/다시 받기/신청하기). 단계는 동작 명사형. 단정 금지 항목은 "[확인필요]".

## 6. 라우팅·핸드오프·운영 규칙

- **분류 신뢰도(분류기 F1, 5-fold CV)**: F1≥0.80(출결·LIVE·정산·대기·설명회) = auto / 혼동쌍(입반↔대기↔퇴원, 진도↔교재) = 1-step 명확화 / 컴플레인(F1 0.39) = 즉시 핸드오프.
- **개인 데이터 조회(T2)**: 본인확인 통과 전제. 미인증 시 잠금 + 본인확인 유도.
- **능동 트리거(GA4)**: `/inbound/payment` 진입 → 미납 카드 배너 / `/classes` → 수업·출결 / `/auth` → 계정.
- **운영시간**: 평일 10–20시 사람 응대. 외 시간 = 즉답·조회 24시간 + 접수 큐.
- **개인정보**: 본인확인·조회는 본인 데이터만. 상담원 전달은 최소 식별 + 사용자 동의. 미성년 데이터 — 법정대리인 동의(개발 [확인필요]).
