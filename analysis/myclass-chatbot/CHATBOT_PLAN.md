# 마이클래스 챗봇 "마이클래스 도우미" — 컨텐츠·플로우·구성 기획서

> 범위: **케이스 컨텐츠 · 대화 플로우 · 정보구조(IA)**. (비주얼/스타일은 별도 문서)
> **SSOT**: `prototype.html` — 명칭·메뉴·노드·카피의 최종 기준. 본 문서의 IA·플로우는 prototype을 따른다.
> 명칭·호칭: 챗봇 = **마이클래스 도우미**(서브타이틀 "문제를 바로 해결하도록 도와드려요"). 사람 호칭 = **상담 선생님**(NOT 실장). 사람 연결처 = **대치 캠퍼스 고3 상담실**. 데모 사용자 = 김시대님 / 대치 캠퍼스(고3). 상태 노드 약 81개·막다른 길 0.
> 근거: AMS 상담 **424,200건(중분류 99종 전수)** + 카카오 16,142 + GA4 785,841. 모든 분기에 실볼륨을 단다.
> 원칙: ① 빈도 높은 케이스를 얕은 깊이(=빠른 도달)에 배치 ② 조회는 자동/개인화, 판단·거래는 사람(상담 선생님) ③ 막다른 길 금지(항상 다음 행동) ④ 등록 연락처·송장 마스킹, 본인 전용 가상계좌·상담실 번호는 전체 노출+복사.

## 3. 정보구조 (IA) — 전체 메뉴 트리 (prototype `MENU`/`NODES` 기준)

> 로그인된 앱 세션에서 챗봇 오픈 → 별도 본인확인 게이트 없이 개인화 첫 인사. 홈 = 8타일 그리드 + "자주 찾는 것" 칩 3개(환불 되나요?→환불 안내 / 보강 어떻게 봐요?→동영상 보강 / 앱이 안 돼요→앱 오류).

```
[챗봇 오픈] → [첫 인사: "안녕하세요, 김시대님. 대치 캠퍼스 기준으로 안내해 드릴게요"] → [홈]

홈 (8 타일, prototype MENU 순서)
├─ ① 🔑 계정·로그인·앱 (account)
│   ├─ 로그인이 안 돼요 ▸ 통합회원 연결 확인 / 아이디·비번 안내(통합회원 이메일 아이디·비밀번호, 아이디 찾기·비밀번호 재설정) / 카톡 기술 상담
│   ├─ 통합회원·계정 연결 ▸ [Guide] ▸ 통합회원·자녀 계정 연결 = 상담 선생님
│   └─ 앱이 안 돼요 ▸ 4증상(흰 화면 / 튕김·꺼짐 / 업데이트 후 / 설치 불가) → 자가해결 → 기술 카톡(handoffTech)
├─ ② 💳 미납·결제·환불 (pay)

│   ├─ 결제 문자 다시 받기 ▸ 미납 건별 또는 전체 한 번에
│   ├─ 결제가 안 돼요 ▸ 다시 시도(납부하기 화면) / 결제문자 / 그래도 안 됨→상담실

├─ ③ ✏️ 입반·등록·대기 (enroll)
│   ├─ 수강신청·입반 ▸ 영역(국/수/과/영)→강좌 2단(REGCOURSES) ▸ 수강신청 화면 / 신청 링크 문자
│   ├─ 내 등록 확인 ▸ [EnrollCard 강좌명 전체·강좌별 상태·강좌별 결제일 상이]

컴플레인(F1 0.39·민감): 추측 응답 금지 → 즉시 상담 선생님 연결
```

## 6. 라우팅·사람 연결·운영 규칙

- **분류 신뢰도(분류기 F1, 5-fold CV)**: F1≥0.80(출결·LIVE·정산·대기·설명회) = auto / 혼동쌍(입반↔대기↔퇴원, 진도↔교재) = 1-step 명확화 / 컴플레인(F1 0.39) = 즉시 사람 연결.
- **개인 데이터 조회(T2)**: 로그인 앱 세션의 학생·지점 전제. 세션 정보로 본인 데이터만 조회.
- **사람 연결 3채널**: 학원 운영 상담=상담실(handoff·전화/문자) / 기술 문제(로그인·앱·영상·특강 인증)=마이클래스 카톡(handoffTech) / 라이브 일반 상담=LIVE 카톡(handoffLive).
- **진입 배너(GA4)**: `/inbound/payment` → 결제 배너(결제가 안 돼요) / `/auth`·`/app` → 로그인 배너(계정·로그인·앱) / 특강 신청 → 특강 본인인증 배너.
- **운영시간**: 평일 사람 응대. 늦은 시간(22–08시) = 즉답·조회는 가능, 사람 연결은 "문자 남기면 운영 시작 시 먼저 연락".
- **개인정보**: 조회는 로그인 본인 데이터만. 등록 연락처·송장은 마스킹, 본인 전용 가상계좌·상담실 번호는 전체 노출+복사. 미성년 데이터 — 법정대리인 동의(개발 [확인필요]).
