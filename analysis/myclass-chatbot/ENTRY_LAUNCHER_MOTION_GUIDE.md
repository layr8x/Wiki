## 1. 왜 이 컴포넌트가 별도로 존재하나

`#openBtn`은 **챗봇 내부 화면이 아니라, 챗봇을 열기 전 "호스트 앱(마이클래스 앱) 자체의 헤더"에 있는 버튼**이다. 기존 Figma 파일(`1032:54`)은 챗봇이 이미 열린 이후의 대화 화면들만 담고 있었고, 이 진입 버튼은 지금까지 **Figma에 한 번도 만들어진 적이 없었다** - 순수하게 코드(CSS 애니메이션)로만 반복 다듬어져 왔다(관련 커밋: `#241`·`#242`, 2026-06-30).

이번 작업의 목적: ① 코드에만 있던 이 버튼을 Figma에 **정식 컴포넌트**로 만들고, ② Figma의 신규 모션(키프레임 타임라인) 기능으로 실제 애니메이션을 **1:1로 이식**해 디자인 리뷰·핸드오프가 가능하게 하고, ③ 정확한 수치 스펙을 문서로 남긴다.

## 3. 상태(State) 스펙

| 상태 | 트리거(코드) | 시각 변화 |
|---|---|---|
| **Idle** | 기본값 | 미소 숨김(`opacity:0`), 아이콘 미세 scale 호흡 + 이중 글로우 호흡 재생(4장) |
| **Hover** | `:hover` | `bub` `translateY(-1.5px)`(.32s), `face` 그룹(눈+미소) `translateY(-2px)`(.32s), 미소 노출(`opacity:1`), **아이콘 호흡 일시정지**(`animation-play-state:paused`), **글로우가 순간적으로 밝고 크게 반응**(`.28s`) |

## 4. 모션 스펙 - "미니멀 + 표정" (6차, 현재 프로덕션)

### 4-0. 현재 모션 (코드 정본, `public/myclass-chatbot.html:66-87` 부근)

> **6차 개정(2026-07-02, 방향 전환) - 5차까지의 글로우·블러·스펙큘러 노선을 전부 폐기.** 5차 배포 후에도 사용자가 "아주 별로다, 나아진 게 없다"고 재차 지적했고, 원인을 캐물은 결과 **"내 미감(디자인 판단력) 자체가 문제"**라는 답을 받음 - 세부 색·각도 조정으로 해결될 문제가 아니라고 판단해, 사용자에게 구체적 레퍼런스를 요청. **Face ID 웃는 얼굴 GIF·Face ID 스캔→완료 전환 GIF(2종)·핀터레스트 3개(모찌·베이맥스·Face ID)** 총 6개를 받아 프레임 단위로 분석한 결과, 공통점이 명확했다:
> - **글로우·블러·반사광이 전혀 없다.** 전부 완전 플랫 - 선 하나, 혹은 단색 채움뿐.
> - **색이 거의 없거나 아주 절제됨.** Face ID 웃는 얼굴은 회색/검정 하나뿐, 나머지도 채도 있는 원색을 그라데이션 없이 그대로 씀.
> - **모션의 중심은 "표정"**: 눈 깜빡임 + 아주 미세한 고개 갸웃 정도가 대기 상태의 전부.
> - **화려한 3D 회전(동전처럼 옆으로 뒤집히는 것)은 계속 도는 장식이 아니라, 상태가 바뀌는 "그 순간 한 번만"** 쓰이는 전환 연출(Face ID의 스캔 중→완료 전환에서 원이 회전하며 파란색→초록 체크로 바뀜).
>
> **결론**: 5차까지 쌓아온 글로우(`::before`/`::after`)·스펙큘러 스윕(`.sheen`)·계속 도는 3D 틸트·스프링 이징을 **전부 제거**. 대신 ①대기 = 눈 깜빡임(변경 없음) + 아주 미세한 `rotate` 갸웃 ②호버 = 절제된 `scale(1.05)`만 - 으로 재구성했다.
>
> **클릭 "동전 뒤집기"는 도입 직후 제거함.** 처음엔 Face ID의 스캔→완료 전환(원이 회전하며 상태가 바뀜)을 참고해 클릭 시 `rotateY(0→360deg)` 1회 스핀을 넣었으나, 사용자 피드백: "저 회전 존나 촌스러운데 내가 준 레퍼런스가 겨우 저런 수준이었어?" - **레퍼런스가 아니라 내 구현이 문제였다.** Face ID의 회전은 회전이 끝나는 시점에 "다른 결과물(체크마크)"을 보여주는 것이 핵심이었는데, 이 챗봇 아이콘은 클릭해도 아이콘 자체가 다른 걸로 바뀌지 않는다 - 즉 보여줄 새 결과가 없는데 그냥 뱅글뱅글 돈 것이라 의미 없는 "스핀 쇼"로 보였던 것. 레퍼런스를 흉내내려면 형태만 베낄 게 아니라 **그 모션이 존재하는 이유(상태 전환의 시각적 은폐)까지 맞아야** 한다는 교훈. → 클릭 피드백은 다시 `:active{scale(.8333)}` 프레스 하나로 단순화.

| 레이어 | 대상 | 애니메이션 | 주기·duration | easing |
|---|---|---:|---:|---|
| 고개 갸웃 | `svg` (아이콘 전체) | `otilt`: `rotate(0deg↔2deg)` | 5s 무한 | ease-in-out |
| 눈 깜빡임 | `.eye`×2 | `oblink` (4-2장, 변경 없음) | 3.4s 무한 | ease-in-out |
| 호버 진입 | `svg` | `animation:none`(갸웃 완전 정지) + `scale(1.05)` | .28s | `var(--ease-spring)`(살짝 튕기는 애플식 스프링) |
| 호버 진입 | `.bub` | `translateY(-1.5px)` | .26s | `var(--ease-ios)`(애플 표준 커브) |
| 호버 진입 | `.face` | `translateY(-2px)` | .26s | `var(--ease-ios)` |
| 호버 진입 | `.smile` | `opacity:0→1`(.22s `var(--ease-ios)`), `scaleY(.45→1)`(.3s `var(--ease-spring)`, 살짝 통통 튀며 안착) | .22~.3s | 혼합 |
| 프레스(클릭 피드백) | 컨테이너 | `scale(.8333)` | .08s | `var(--ease-ios)` |

**색**: 완전 무채색 - `--icon-primary:#161616`(진한 회흑색) 하나만 사용. 5차까지 있었던 `--glow-tint`·글로우·스펙큘러용 파란 색상 전부 제거.

**애플 스타일 이징 리파인(6차 내 소개정, 2026-07-02)**: 사용자 요청 "챗봇 모션 애플 스타일로 디벨롭해" 반영 - 새 이펙트를 더 추가하는 게 아니라(4-0장의 "미니멀" 결론 유지), **기존 상호작용의 타이밍·이징만** 애플식으로 다듬음. 파일에 이미 있던 `--ease-ios:cubic-bezier(.32,.72,0,1)`(애플 UIKit 표준 커브)를 호버 반응(`.bub`·`.face`·프레스)에 적용하고, 살짝 튕기는 스프링감이 필요한 곳(호버 스케일·스마일 등장)엔 신규 `--ease-spring:cubic-bezier(.34,1.56,.64,1)`을 적용. 지속시간도 토스식 .32s→애플식 .22~.28s로 살짝 단축(애플 인터랙션은 더 즉각적으로 반응).

> ⚠️ **버그 발견·수정(이 소개정에서)**: 호버 시 `scale(1.05)`가 실제로는 **한 번도 적용된 적이 없었다** - `animation-play-state:paused`로 `otilt` 애니메이션을 "일시정지"만 시켰는데, **CSS 스펙상 일시정지된 애니메이션도 여전히 그 속성(transform)을 점유**해서 같은 속성을 바꾸려는 `transform:scale(1.05)`+`transition`이 씹혔음(4-0장의 `:not(.flip)` 버그와 같은 계열 - "애니메이션이 트랜지션을 가린다"). Playwright로 호버 중 `getComputedStyle().transform`을 직접 찍어 `scale(1.05)`가 전혀 반영 안 되는 걸로 확인. **해결**: `animation-play-state:paused` → `animation:none`(완전 정지, 속성 소유권 반납). 재검증 결과 정상적으로 `scale(1.05)`에 도달함을 확인.

**아이콘 도형(bub) 정밀도 수정**: 사용자가 원본 Figma(`node-id=1991-2632`, Flow-5 쇼케이스)를 직접 지목하며 "라운드 값도 다르고 선 굵기도 다른 것 같다"고 지적. 실제로 코드의 말풍선(`bub`) 경로가 **완전 직각 코너**(`M3 4.5H21V16.5H7L3 20.5V4.5Z`, `stroke-linejoin:miter`)였던 반면, Figma가 export한 실제 벡터(`get_design_context`로 노드의 `imgBub` 에셋 URL을 받아 raw SVG를 직접 curl로 다운받아 확인)는 **모서리 radius ≈1(19.5×17.15 뷰박스 기준), 꼬리도 직선이 아니라 곡선으로 부드럽게 이어지는 모양**이었다. 근사가 아니라 **Figma의 실제 path 좌표를 그대로 가져와 내 24×24 뷰박스 좌표계로 평행이동**(dx=+2.25, dy=+3.75 - 두 좌표계의 사각형 본체 바운딩박스가 정확히 일치하도록 계산)해서 교체: `M3 5.5C3 4.94772 3.44772 4.5 4 4.5H20C20.5523 4.5 21 4.94772 21 5.5V15.5C21 16.0523 20.5523 16.5 20 16.5H7.41421C7.149 16.5 6.89464 16.6054 6.70711 16.7929L3.42678 20.0732C3.26928 20.2307 3 20.1192 3 19.8964V5.5Z`. 눈(`rx="1"`)·웃는 입(`stroke-linecap:round`, 4유닛 곡선)은 대조 결과 이미 Figma와 일치해 손대지 않음. 스트로크 두께는 원래도 `1.5`로 Figma와 동일했음(이번 지적은 "다른 것 같다"는 인상이었지 실측 차이는 아니었던 것으로 확인 - 코너 radius 쪽이 실제 차이였음).

**검증**: Playwright로 idle 5s(고개 갸웃 한 주기)·hover 전환+유지 프레임을 캡처해 애니메이션 GIF로 합성 후 육안 확인. bub 경로 수정은 Figma에셋 URL에서 받은 raw SVG의 좌표를 코드로 그대로 옮긴 것이라 근사치가 아니라 수학적으로 정확히 일치 - 픽셀 비교보다 좌표 일치가 더 신뢰도 높은 검증. 빌드·린트·테스트(206개) 통과.

### 4-1. 폐기된 5차 이전 스펙 (참고용, 코드와 다름)

> ⚠️ 5차(글로우+스펙큘러 스윕+스프링 3D 틸트), 4차(글로우+3D 틸트), 3차(소프트 글로우 호흡+클릭 리플) 전부 6차로 대체되며 폐기됨. "화려한 이펙트"가 정답이 아니라 "미니멀+표정"이 정답이었다는 이번 세션의 핵심 교훈 - 다음에 이 컴포넌트를 다시 만질 일이 있으면 **레퍼런스부터 다시 확인**하고, 사용자가 "화려하게"라고 말해도 곧이곧대로 글로우·블러부터 추가하지 말 것.

**참고 레퍼런스 영상/GIF 분석 방법 메모**: 이 세션에서 사용자가 올린 mp4를 분석해야 했는데, 이 샌드박스의 Chromium은 특허 코덱(H.264) 디코더가 없는 오픈소스 빌드라 `<video>` 태그로 직접 재생이 안 됨(`DEMUXER_ERROR_NO_SUPPORTED_STREAMS`). `apt-get install ffmpeg`도 미러 404로 실패. **해결**: `pip install imageio-ffmpeg`로 정적 ffmpeg 바이너리를 받아(`imageio_ffmpeg.get_ffmpeg_exe()`) 프레임을 PNG로 추출. GIF는 PIL의 `Image.open()`+`ImageSequence`로 바로 프레임 추출 가능(ffmpeg 불필요). Pinterest 단축 링크(`pin.it/...`)는 `WebFetch`로 2~3단계 리다이렉트(pin.it → api.pinterest.com → pinterest.co.kr → kr.pinterest.com)를 따라가야 도착하고, 그마저도 실제 핀 이미지 URL은 JS 렌더링 없이는 안 나와 **핀 제목·설명 텍스트로만 유추** 가능했음(이번엔 제목만으로도 충분히 방향을 파악할 수 있었음).

**변경 이유(3차, 유지)**: 기존엔 딱딱한 링(`obeacon`)이 대기 중에도 계속 순환해 "펄스가 단순하다"는 피드백을 받았다. 앰비언트는 부드러운 글로우 호흡으로, 명확한 피드백이 필요한 순간(클릭)엔 리플을 **그때만** 터뜨리는 것으로 역할을 분리해 더 정제된 느낌을 의도.

### 4-1 ~ 4-3. 이전(1~2차) 앰비언트 모션 - Figma 빌드에 남아있는 스펙 (참고용, 코드와 다름)

> ⚠️ **아래는 3차 개정 이전(=Figma 키프레임 타임라인에 아직 남아있는) 스펙이다.** 코드는 이미 위 4-0장(4차)으로 교체됐고, **Figma 쪽 모션은 아직 3차/4차로 동기화되지 않았다**(7장 참고). 아이콘 바운스(`Icon` 프레임의 점프+갸웃)와 비콘 링(하드엣지 핑)은 **더 이상 프로덕션에 없다** - 역사적 기록 + Figma 재동기화 시 참고용으로만 남긴다.

### 4-4. 검증 결과

**1차 개정**: `export_video`로 6.17초 클립을 렌더링해 0.64s(비콘1 피크)·1.16s(눈 감김)·2.09s(비콘2 피크)·4.08s(점프 피크) 프레임을 확인 - 코드와 시각적으로 일치. 위 표의 **타이밍·이징 수치는 2차 개정에서도 변하지 않았다**(사용자가 바꾼 건 도형·색·크기이지 모션 타이밍이 아님).

**2차 개정 시 발견**: 사용자가 눈을 원형→캡슐로 다시 그리면서 **새 eye 노드로 교체**돼(`eye_l`/`eye_r` 노드 ID 변경) 눈깜빡임(`oblink`) 키프레임이 유실되어 있었음 - Figma 파일에 동일 스펙(4-2장)으로 **재적용 완료**(프로덕션 코드는 CSS 클래스 기반이라 애초에 영향 없었음). `Icon` 프레임의 바운스(4-1장)·비콘 링(4-3장) 키프레임은 노드 정체성이 유지돼 그대로 살아있었다.

## 5. 인터랙션 전환 - Figma 프로토타이핑(reactions), 2차 시점 기준

> ⚠️ 이 섹션은 **2차 개정 시점**에 연결한 Figma reactions 기록이다. 3차의 "호흡 정지 + 글로우 반응"(4-0장)은 Figma에 아직 반영되지 않았다 - Figma를 열면 지금도 5장 표의 동작(위글·컨테이너 트랜지션)이 재생된다.

Hover·Pressed는 정적 변형일 뿐 아니라, **Figma 프로토타입(reactions)으로 실제 스와이프 전환까지 연결**했다. Figma에서 `1978:2636`(Entry Launcher Variant Set)을 Present 모드로 열어 마우스를 올리고/눌러보면 전환된다.

| 전환 | 트리거(Figma) | 대상 | duration | easing(Figma) |
|---|---|---|---:|---|
| Idle → Hover | `ON_HOVER`(while hovering, 자동 되돌림) | `State=Hover`(`1978:2622`) | .34s | `CUSTOM_CUBIC_BEZIER {.34,1.56,.64,1}` |
| Hover → Pressed | `ON_PRESS`(while pressing, 자동 되돌림) | `State=Pressed`(`1978:2629`) | .1s | `EASE_OUT` |

두 트리거 모두 Figma의 "누르고 있는/올리고 있는 동안"(self-reverting) 의미라 - 마우스가 떠나거나 손을 떼면 별도 역방향 reaction 없이 자동으로 이전 상태로 복귀한다.

## 6. 접근성

코드에 `prefers-reduced-motion: reduce` 가드가 있음 - 이 값이 켜지면 `obreathe`·`oblink`·글로우 애니메이션이 전부 꺼지고, `face`/`smile` 트랜지션도 즉시 전환되며, 클릭 리플은 스케일 없이 짧은 opacity 페이드로만 대체된다(코드 마지막 `@media (prefers-reduced-motion:reduce)` 블록). **Figma 빌드에는 이 축소-모션 변형을 별도로 만들지 않았다** - 개발 시 코드의 미디어쿼리 가드를 그대로 유지할 것.

## 7. 의도적으로 생략한 것 · Figma-코드 간극 (정직하게 기록)

- **Figma 모션이 3차 개정을 반영하지 않음**: 4-0장(현재 코드 모션)은 이번 세션에서 코드만 재설계했다. Figma의 키프레임 타임라인(4-1장~4-3)과 reactions(5장)는 여전히 **2차 시점 모션**(점프+갸웃 바운스, 하드엣지 비콘 링, 위글)을 담고 있다 - Figma를 열어 재생해보면 코드와 다르게 보인다. 필요하면 후속 작업으로 Figma도 4-0장 스펙(글로우 호흡·클릭 리플)에 맞춰 재동기화할 수 있다.
- **Hover의 중간 디테일**: (2차 기준 기록) Smart Animate는 시작~끝 상태만 보간해 세부 트랜지션 타이밍까지는 재현하지 않았다.
- **눈 깜빡임의 무한 반복**: 4-2장에서 설명한 대로, Figma 6초 타임라인엔 대표 1~1.5사이클만 배치. 실제 반복 주기(3.4s)는 이 문서 표가 정본.
- **개발 시 우선순위**: Figma 빌드는 **디자인 검토·시각 스펙 확인용**이다. 실제 구현은 항상 `public/myclass-chatbot.html`의 CSS(`#openBtn` 관련 규칙)를 정본으로 사용할 것 - 이 문서는 그 CSS를 사람이 읽기 쉬운 표로 옮긴 것이지, CSS를 대체하지 않는다.
