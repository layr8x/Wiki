## 1. 제품 비전 & 문제 정의

### 1.1 비전 (한 문장)

> **"학부모·학생이 전화·카카오로 묻던 학원 운영 질문을, 앱 안에서 30초 안에 스스로 해결하게 한다."**

마이클래스 챗봇은 *상담 채널*이 아니라 **셀프서비스 레이어**다. "사람을 빨리 연결하는 봇"이 아니라 "사람을 부를 필요가 없게 만드는 봇"을 지향한다.

### 1.2 문제 정의 (데이터 근거)

| # | 문제 | 데이터 근거 | 비즈니스 임팩트 |
|---|---|---|---|
| P1 | **상담의 96.7%가 전화** — 셀프서비스 수단이 없음 | AMS 410,104건이 전화 접수(424,200 중) | 상담원 인건비·대기시간·야간 미응대 |
| P2 | **앱에서 막히는 것 1위 = 계정·로그인·앱 (디지털 36.7%)인데 전화로는 안 물음(0.2%)** | 카카오 오픈채팅 2,639대화(1위) vs AMS 998건(0.2%) | 막힌 사용자가 *앱 밖*으로 이탈해 카카오로 감 → 앱 안에서 못 잡음 |
| P3 | **단순 조회를 사람이 처리** — 회차/강좌 조회·문자 재발송이 전화의 큰 덩어리 | AMS 상담내용 최빈어 '주차' 42,484·'회차' 20,445, 동영상보강 32,358·동보자료 31,690, '문자' 15,818 | 자동화 가능한 일을 사람이 함 (낭비) |
| P4 | **결제 재시도 마찰 + 미납 잔여** (※ "이탈 61%"는 측정 착시) | 실사용자 결제완료 ~80%(정상). 1인당 `enter_payment` 평균 3.37회. 미납 8,954건 | 이탈 손실은 과장이었으나, 재시도 마찰·미납 회수는 실재 |
| P5 | **입반·대기 수요가 전화에 갇힘** — 디지털 셀프 미충족 | AMS 입반 93,478·대기 26,724, 재수강확인 10,965·대기번호 3,170·충원 11,523 | 단순 상태조회까지 전화로 처리 |

> **착시 정정(중요)**: v1/v2에서 "결제 이탈 61% = 최대 손실"이라 한 것은 **틀렸다**. 원천 이벤트(`events_*`)를 직접 분석하니 실사용자 기준 결제완료 ~80%(정상). 외부 결제모듈(sdijeon 공통 PG) 왕복이 GA4상 "빈 구간"으로 보였던 것. → 결제 메뉴의 가치는 "이탈 막기"가 아니라 **미납 회수 + 재시도 마찰 완화 + 외부모듈 왕복 안내**(톤 = "도와주기").

### 1.3 핵심 통찰 — 전화와 디지털은 정반대다

| | AMS 전화 1위 | 디지털(오픈채팅) 1위 |
|---|---|---|
| **무엇** | 출결 30.7% | 계정·로그인·앱 36.7% |
| **왜** | 출결은 앱에서 *잘 써서* 전화로만 물음(GA4 `/classes` 216만 = 정상 작동) | 디지털은 *막혔을 때* 찾는 곳(앱 안 됨·로그인·등록·결제·환불) |

→ **챗봇은 앱 안에 산다 → 디지털 기준으로 메뉴를 배치한다.** 출결·시간표는 "도움요청"이 아니라 "**조회 기능**"으로 둔다.

## 2. 목표 & 성공지표 (KPI)

> 측정 가능 정의 + 목표치 + 산정식. **가설 기반 목표치는 [가설]로 명시**. 베이스라인이 없는 초기 출시이므로, 출시 후 2주를 베이스라인 측정 구간으로 둔다.

### 2.1 North Star Metric (단 하나의 지표)

> **디플렉션율 (Deflection Rate) = 챗봇 세션 중 상담원 연결 없이 종료된 비율**

- **정의**: `(챗봇 세션 수 − 상담원 에스컬레이션 세션 수) ÷ 챗봇 세션 수`
- **목표치(v1)**: **≥ 55%** [가설 — v2 커버리지 추정 50~60% 근거]
- **의미**: 셀프서비스 흡수의 단일 대리지표. 모든 메뉴 설계가 이 숫자로 수렴.

### 2.2 KPI 트리

| 영역 | 지표 | 정의(산정식) | v1 목표 | 근거 |
|---|---|---|---|---|
| **흡수(NSM)** | 디플렉션율 | 비-에스컬레이션 세션 ÷ 전체 세션 | **≥55%** [가설] | v2 커버리지 50~60% |
| 흡수 | 1차 자동응답 해결율 (Self-Serve Resolution) | "해결됐어요" 클릭 또는 핸드오프 없이 종료 ÷ 전체 | **≥45%** [가설] | T1+T2 케이스 비중 |
| 흡수 | 채널 전환(전화→챗봇) | 챗봇 세션 수 / (챗봇+전화 접수) 추세 | 출시 후 ↗ 추세 | 전화 96.7% 흡수가 핵심 |
| **계정·앱** | 계정·앱 해결율 | 🔑 진입 세션 중 비-에스컬레이션 ÷ 🔑 진입 | **≥50%** [가설] | 디지털 1위 36.7%, 대부분 가이드(T1)로 해결 가능 |
| **결제·미납** | 미납 회수 보조 | N2 알림 발송 후 7일 내 결제완료 ÷ 알림 대상 | **≥25%** [가설] | 미납 8,954·D-3/D-1/D-day |
| 결제 | 결제 재시도 자가해결율 | [결제가 안 돼요] 진입 중 비-에스컬레이션 ÷ 진입 | **≥40%** [가설] | 1인 3.37회 재시도 마찰 |
| **입반·대기** | 대기/재수강 조회 흡수 | ✏️ 조회형(재수강·대기번호·충원) 자가완결 ÷ 진입 | **≥50%** [가설] | 재수강 10,965·대기번호 3,170·충원 11,523 |
| **품질** | 상담원 재질문율↓ | 핸드오프 후 상담원이 식별정보 재질문한 건 ÷ 핸드오프 | **≤10%** [가설] | 맥락칩 자동첨부(기기·OS·앱버전·시도단계) |
| 품질 | 에스컬레이션율↓ | 상담원 연결 세션 ÷ 전체 (= 1−디플렉션) | **≤45%** | NSM 보수치 |
| 품질 | CSAT(만족도) | 종료 시 별점 평균 | **≥4.0/5** [가설] | 종료 만족도 수집 |
| **참여** | 본인확인 통과율 | 본인확인 성공 ÷ 본인확인 시도 | **≥80%** [가설] | 2필드 폼(form_submit 15만 마찰 완화) |
| 참여 | 능동알림 옵트인율 | 알림 동의 ÷ 노출 | 측정만(베이스라인) | N2/N4/N1 |

### 2.3 측정 인프라 [확인필요 — 개발]

- 모든 노드에 이벤트 로깅: `chatbot_open`, `menu_select`, `node_view`, `resolved_yes`, `escalate`, `notif_optin`, `notif_click`, `csat`.
- 세션 정의: 모달 오픈 ~ 종료(또는 30분 idle).
- 상담원 재질문율은 상담 시스템과 연계 필요 → v1은 **핸드오프 시 맥락칩 첨부 여부**(전달 완전성)를 대리지표로.

## 3. 우선순위 (MoSCoW)

> Must = 6/18 핸드오프 필수 · Should = 빠른 후속 · Could = 여유 시 · Won't = 이번 범위 밖.
> 분류 기준: **디지털 채널 볼륨 × 자가해결 가능성 × 데이터 의존도(낮을수록 빠름)**.

### 3.1 메뉴 8종

| 메뉴 | 디지털 볼륨 | 자가해결성 | 분류 | 근거 |
|---|---|---|---|---|
| 🔑 **계정·로그인·앱** | 36.7% (1위) | 높음(대부분 가이드 T1) | **Must** | 디지털 압도적 1위, 본인확인 우회로 즉시 가능, DB 의존 낮음 |
| 💳 **미납·결제·환불** | 12.2% (양채널 큼) | 중(조회+딥링크) | **Must** | 미납 회수·재시도 마찰. 단 수납 DB 연동 필요 |
| ✏️ **입반·등록·대기** | 7.6% (전화 주도 미충족) | 중(조회형 T2) | **Must** | 재수강/대기/충원 조회가 전화 큰 덩어리 흡수 |

| RefundCard(환불 예상 계산) | v2 | 교육청 환불 규정 확정 후 |
| N3·N5~N9 알림 | v1.x~v2 | 인프라·이벤트 소스 확보 후 |
| LLM 기반 인텐트 분류 정밀화 | v2 | 현재 규칙기반 v1(단일배정), 추후 상향 |

### 4.3 v1 디플렉션 가설 (왜 이 범위로 충분한가)

디지털 1·2·3위(🔑 36.7% + 💳 12.2% + ✏️ 7.6%) = **디지털 상담의 ~56%를 직접 겨냥**. 여기에 🎧 핸드오프 안전망(기타 28.3% 중 FAQ 자가완결분)을 더하면 **디플렉션 55% 목표가 데이터상 도달 가능**. 출결·라이브는 디지털 볼륨이 낮아(3.1%·6.0%) v1 제외해도 NSM 손실이 작다.

## 5. 기능별 인수기준 (Acceptance Criteria) — 상위 6개

> Given-When-Then 형식. 각 시나리오는 `QUICK_MENU_SCENARIOS.md`/`CHATBOT_PLAN.md`의 플로우에 대응.

### AC-1. 🔑 계정·로그인·앱 (본인확인 우회)

```
Given 사용자가 로그인/앱 문제로 챗봇을 열었고 (또는 /auth·/app 페이지에서 진입)
When  [로그인이 안 돼요] / [앱이 멈춰요] / [통합회원·계정연결] / [본인확인이 안 돼요] 중 선택하면
Then  본인확인 게이트 없이(우회) 즉시 GuideCard(번호 단계 가이드)를 보여준다
And   각 카드 하단에 [해결됐어요](종료) / [아직 안 돼요 → 상담원] 행동이 항상 존재한다
And   [아직 안 돼요]로 핸드오프 시 진입경로·기기·OS·앱버전·시도단계가 맥락칩으로 자동 첨부된다
```
- **수용 조건**: 로그인 불가 사용자가 본인확인에 다시 막히지 않는다(우회 검증). 막다른 길이 0개.

### AC-2. 💳 미납·결제 (조회 + 딥링크 + 문자 재발송)

```
Given 본인확인을 통과한 사용자가 💳 메뉴에서 [미납·납부 현황]을 선택하면
When  수납 DB를 조회하면
Then  DataCard에 미납 합계·항목·기한이 표시되고, 주행동 [지금 결제하기](딥링크)·보조 [결제문자 다시 받기]가 노출된다
And   [결제문자 다시 받기] 선택 시 마스킹된 번호(010-****-1234)로 발송하고 "보냈어요 📩"를 확인시킨다
And   [결제가 안 돼요] 분기에서 외부 결제창(sdijeon) 왕복을 안내하고, 4갈래(카드거절·화면멈춤·금액확인·미반영)로 자가해결을 제공한다
```
- **수용 조건**: 결제 톤은 "이탈 막기"가 아니라 "도와주기". 딥링크는 외부 PG로 정확히 연결.

### AC-3. ✏️ 입반·등록·대기 (조회형 자가완결)

```
Given 본인확인을 통과한 사용자가 ✏️ 메뉴에서 [내 등록·재수강 확인] / [대기 번호 확인]을 선택하면
When  수강/대기 DB를 조회하면
Then  DataCard에 강좌·등록상태·다음결제일(재수강) 또는 강좌·대기번호 N(대기)을 표시한다
And   등록완료 → "정상이에요 ✅" / 결제대기 → [지금 결제(→💳)] / 대기 → [대기 알림(→N4)]로 다음 행동을 잇는다
And   조회 키는 강좌 단위이며, 거래(입반 신청·전반)는 핸드오프로 라우팅한다
```
- **수용 조건**: 재수강확인·대기번호 조회가 사람 연결 없이 완결된다.

### AC-4. 🎧 상담원 핸드오프 (3단계 표준 + 운영시간 분기)

```
Given 자가해결이 안 되어 [상담원 연결]을 선택하면
When  핸드오프를 시작하면
Then  ① HandoffCard에 전달내용(학생 마스킹·문의유형·직전 시도)과 동의 체크박스를 보여주고
And   ② 동의 후 접수번호(예: #A-2026-0617-031)를 발급하며
And   ③ 운영중(평일 10–20시)이면 "평균 N분 대기"+[급하면 전화], 운영외면 "10시 1순위 연결, 급한 건 셀프 24시간"으로 분기한다
And   맥락칩이 자동 첨부되어 상담원이 식별정보를 재질문하지 않는다
```
- **수용 조건**: 동의 없이는 전달 안 됨. 컴플레인은 추측 응답 없이 즉시 최우선 큐.

### AC-5. 본인확인 온보딩 (2필드, 폼리스)

```
Given 사용자가 챗봇을 처음 열면 (스플래시 1.7s)
When  본인확인 단계에서 [학생 이름 + 학부모 연락처 뒷 4자리] 2필드만 입력하면
Then  일치 시 빠른메뉴(8타일)로 진입하고, 2회 불일치 시 상담원으로 연결한다
And   🔑 계정·로그인 블록은 이 게이트를 우회한다(로그인 불가자 보호)
```
- **수용 조건**: 입력 필드는 정확히 2개(form_submit 15만 마찰 완화). 본인 데이터만 조회.

### AC-6. 능동 알림 N2 (미납) — MVP 알림

```
Given 사용자가 납부 알림에 옵트인했고, 미납이 발생하면
When  기한 D-3 / D-1 / D-day 시점이 되면
Then  "7월 수강료 미납, 기한 D-2" 메시지와 [지금 결제]·[문자 다시] 액션을 푸시한다
And   1인/일 3건 한도·야간(21–08) 금지·번호 마스킹·중복발송 차단 규칙을 지킨다
And   알림 클릭 → 7일 내 결제완료를 미납 회수 KPI로 집계한다
```
- **수용 조건**: 옵트인 없으면 미발송. N4(대기충원)만 야간 예외 허용.

## 6. 범위 밖(Out of Scope) · 가정(Assumptions) · 의존 리스크(Dependencies & Risks)

### 6.2 가정 (Assumptions)

1. 본인확인은 [학생명 + 학부모 뒷4자리] 매칭으로 충분하다(2필드).
2. 결제는 외부 PG로 딥링크 이동 후 `complete_payment` 콜백으로 확인된다.
3. 미납·재수강·대기·출결 데이터는 조회 API로 실시간 접근 가능하다.
4. 상담 운영시간은 평일 10–20시. 외 시간은 접수 큐로 처리.
5. 디지털 채널 분포(오픈채팅 7,213 분류)가 챗봇 실제 수요를 대표한다.
6. v1 디플렉션 베이스라인은 출시 후 2주간 측정으로 확정한다.

| # | 의존 항목 | 영향 메뉴 | 리스크 | 미충족 시 폴백 |

| 3 | 가입수단 조회 API(소셜 종류 반환) | 🔑 (Must) | 中 | 일반 가이드만(T1) |
