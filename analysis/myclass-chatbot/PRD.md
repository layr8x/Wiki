## 0. 한 페이지 요약 (Executive Summary)

| 항목 | 내용 |
|---|---|
| **무엇** | 마이클래스 앱(`myclass.sdij.com`) **안에서 뜨는 인앱 챗봇 "마이클래스 도우미"** — 학생·학부모가 막혔을 때 자가 해결, 안 되면 맥락 그대로 상담 선생님(대치 캠퍼스 고3 상담실)·기술 카톡 채널로 연결 |
| **왜** | 전화 상담 **96.7%**(셀프서비스 미충족). 디지털 채널에선 **계정·로그인·앱이 36.7%로 1위** — 앱 안에서 막히는데 도울 길이 없음 |
| **핵심 가치** | ① 디지털 1위(계정·앱) 셀프 트러블슈팅 ② 미납 회수 + 결제 재시도 마찰 완화 ③ 핸드오프 시 "재질문 0" (학생·지점·문의유형 자동 첨부) |
| **북극성 지표** | **자가해결율**(전화 접수 비중 96.7% → 흡수) |
| **MVP 범위** | 메뉴 8개 + 약 81개 상태 노드(막다른 길 0) + 3채널 연결(상담실·기술 카톡·LIVE 카톡) + 진입 맥락 배너 3종(결제·로그인·특강인증) |
| **기한** | 6/18 개발팀 핸드오프(콘텐츠·플로우·디자인 확정본) |

**설계 3원칙** (시나리오 v3 확정):
1. **앱에서 막히는 것(계정·결제·입반)을 앞으로.** 전화 1위 출결은 뒤로 — "회차/강좌 조회 + 문자 재발송"형 *조회 기능*으로 유지.
2. **결제는 "이탈 막기"가 아니라 "도와주기".** 실사용자 결제완료 **~80%**(정상). 가치 = 미납 회수 + 재시도 마찰 완화 + 외부 결제모듈 안내.
3. **모든 조회는 강좌 단위 키.** AMS 상담이 '특정 선생님 강좌' 단위로 일어남.

## 1. 배경 · 문제 · 목표

### 1.1 배경 — 3채널 데이터 교차검증

세 개의 독립 데이터가 **같은 결론**으로 수렴(`DATA_ANALYSIS.md` §6 삼각검증).

| 소스 | 규모 | 무엇을 알려주나 |
|---|---|---|
| **AMS 상담**(상담 선생님 기록) | 424,200건 / 중분류 99종 | 무엇을 물어보나(케이스 유니버스). 전화 96.7%·학부모 92.1% |
| **카카오 오픈채팅**(파트너센터 스트림) | 7,213 대화 / 85,049 메시지 | 디지털 채널 실제 상담. 챗봇이 살 환경에 가장 가까움 |
| **GA4 라이브**(BigQuery) | 세션 192.9만 / 페이지뷰 797.7만 | 어디서 막히나(행동·페이지 맥락·결제 퍼널) |

### 1.2 문제 (Problem Statement)

| # | 문제 | 데이터 근거 |
|---|---|---|
| P1 | **전화에 의존** — 셀프서비스가 없어 단순 조회까지 전화로 옴 | AMS 접수형태 **전화 96.7%**(410,104건) |
| P2 | **디지털에서 계정·앱이 막힘** — 앱 안에서 막히는데 도울 길이 없음 | 오픈채팅 **계정·로그인·앱 36.7%**(압도적 1위) |
| P3 | **결제 마찰** — 미납 잔여 + 재시도 왕복 + 외부 결제모듈 혼란 | 미납 8,954건 · 1인당 결제화면 **평균 3.37회** 재진입 |
| P4 | **입력 마찰** — 폼이 많아 진입 장벽 | `form_submit` **15.3만**건 |
| P5 | **전화 1위 출결은 사실 조회·재발송 수요** | 상담내용 최빈어 '주차 42,484·회차 20,445' = 단순 회차 조회 |

> ⭐ **중요 정정**(`DATA_ANALYSIS.md` §1.5): 초기 "결제 이탈 61%"는 **측정 착시**. 원천 이벤트 재분석 결과 실사용자 기준 결제완료 **78.6%~81.6%**(정상). 외부 결제모듈(sdijeon 공통 PG)을 GA4가 중간 구간을 못 잡았고, 1인당 결제화면 3.4회 재진입으로 이벤트가 부풀려진 것. → **결제 메뉴의 톤은 "이탈 막기"가 아니라 "도와주기".**

### 1.3 목표 (Goals)

| 구분 | 목표 | 측정(KPI) |
|---|---|---|
| **북극성** | 전화 접수 **96.7%를 셀프서비스로 흡수** | 챗봇 자가해결률 + 전화 인입 감소 |
| G1 | 디지털 1위 계정·앱을 챗봇 1급으로 자가 해결 | 🔑 메뉴 자가해결률 ≥ 목표치 |
| G2 | 미납 회수 + 결제 재시도 마찰 완화 | 미납 카드 → 결제 딥링크 클릭률 / 미납 회수율 |
| G3 | 사람 연결 시 "재질문 0" (학생·지점·문의유형 자동 첨부) | 상담 선생님 재질문률 ↓ / 연결 만족도 |
| G4 | 입력 마찰 최소화 | 버튼/카드 기반 결정 트리(자유 입력 최소) |

### 1.4 비목표 (Non-Goals) — MVP 제외

- 자연어 자유 대화(LLM 생성형 답변) — MVP는 **버튼/카드 기반 결정 트리**. 분류기는 라우팅 보조용.
- LIVE 별도 사이트 *내부* 처리(결제·배송 직접 실행) — 안내·딥링크까지만(연동 범위는 §4-D4).
- 능동알림 전체 9종 — MVP는 **N2·N4·N1 3종**만.
- 결제·환불 *금액 확정* — 챗봇은 조회·안내, 확정은 상담원/규정.

### 2.3 사람 연결 — 3채널 분기 (prototype `handoff` / `handoffTech` / `handoffLive`)

> 사람 연결은 문의 성격에 따라 3개 채널로 갈라진다. 모든 채널 카드는 "함께 적어주세요"형 안내(학생 이름·학교·강좌명·증상)로 재질문 0을 지향한다.

| ID | 채널(함수) | 연결처 | 무엇을 보낼 때 | 우선 | 핵심 수용기준(AC) |

## 8. 측정 · 분석 계획 (Measurement Plan)

### 8.1 추적 이벤트 정의

| 이벤트 | 발생 시점 | 핵심 속성(payload) |
|---|---|---|
| `chatbot_open` | 위젯 오픈 | entry_page(page_path), entry_type(능동배너/수동), device |
| `chatbot_greeting` | 첫 인사 노출 | student_known(로그인 세션 식별 여부), branch |
| `menu_enter` | 8메뉴 타일 진입 | menu_id(account/pay/enroll/live/attend/time/quit/help), source(타일/FAQ칩/배너) |
| `node_view` | 카드/가이드 노출 | node_id, tier(T1/T2/T3), card_type |
| `self_resolve` | "해결됐어요" 클릭 | menu_id, node_id |
| `payment_deeplink_click` | `지금 결제하기` 클릭 | menu_id, amount_band(금액 노출X·구간만), from(미납카드/충원) |
| `sms_resend` | "문자 다시 받기" 클릭 | type(결제/자료/증명) |
| `handoff_open` | 사람 연결 시작 | channel(상담실/마이클래스카톡/LIVE카톡), reason, off_hours(22–08 여부) |
| `handoff_action` | 연결 실행 | channel, action(전화 연결/문자 복사/카톡 열기) |
| `notification_sent` / `notification_click` | 능동알림 발송/클릭 | notif_id(N1~N9), action |
| `complaint_route` | 컴플레인 즉시 상담 선생님 | from_node |

> ⚠ 모든 이벤트는 **PII 미포함**(금액·번호 등은 구간/마스킹만). 로그인 세션 식별값은 미적재.

### 8.2 KPI 매핑

| 목표 | KPI | 측정식 |
|---|---|---|
| 북극성: 전화 흡수 | **자가해결률** | `self_resolve` / `chatbot_open` |
| G1 계정·앱 셀프 | 🔑 자가해결률 | M1 `self_resolve` / M1 `menu_enter` |
| G2 미납 회수/결제 마찰 | 결제 딥링크 클릭률 / 미납 회수율 | `payment_deeplink_click` / 미납카드 노출 · (수납 DB 회수) |
| G3 사람 연결 품질 | 연결 전환율 / 재질문률 | `handoff_open` / `menu_enter` · 상담 선생님 재질문 로그 |
| G4 입력 마찰 | 자유 입력 비율 | 자유 입력 노드 / 전체 노드 진입 |
| 능동알림 효과 | 알림 클릭률 / 옵트아웃율 | `notification_click` / `notification_sent` |
| 운영 효율 | 노드별 이탈·자가해결 히트맵 | `node_view` → `self_resolve`/`handoff_open` 경로 분석 |

> **분석 재사용**: 오픈채팅 분류는 Supabase에 저장됨 → 대시보드 RPC(`get_chat_category_distribution`)로 재사용. 기기별 퍼널은 D8 보완 후 정식 채택.
