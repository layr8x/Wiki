# 마이클래스 챗봇 — 빠른 메뉴 · 시나리오 (v3, 디지털 우선)

> **설계 기준 변경**: 챗봇은 **앱 안**에 산다 → 우선순위를 전화(AMS)가 아니라 **디지털 채널(카카오 오픈채팅 + 앱 접속 GA4)** 기준으로 재정렬.
> **근거(검증 완료)**: AMS 상담 424,200 · 카카오 오픈채팅 7,213대화(분류 저장) · GA4 원천 events. 상세·정정은 `DATA_ANALYSIS.md`, 3채널 비교는 `data/통합_3채널비교.csv`.

## 0. 왜 디지털 우선인가 (3채널 비교)

| 메뉴 | 전화(AMS) | 오픈채팅 | 챗봇 의미 |
|---|---:|---:|---|
| 🔑 계정·로그인·앱 | 0.2% | **37.1% (1위)** | 전화론 안 묻고 앱에서 막힘 → **1순위** |
| 💳 미납·결제·환불 | 8.2% | 12.2% | 양쪽 다 큼 → 2순위 |
| ✏️ 입반·등록·대기 | 28.3% | 7.6% | 전화 주도 미충족 수요 |
| 📡 라이브 | 14.9% | 6.0% | |
| 📦 교재·배송 | 1.2% | 5.3% | 디지털서 의외로 큼 |
| 📋 출결·보강 | **30.7%** | 3.1% | 앱에서 직접 사용 → **'조회 기능'으로** |
| 📅 시간표·수업 | 3.1% | 0.2% | 잘 씀(안 물음) → 조회 |
| 🔄 퇴원 | 9.0% | 0.2% | 거의 디지털 0 → 리텐션 플로우만 |
| 🎧 일반·기타 | 2.7% | **28.3%** | "되나요/언제/어디" → FAQ + 사람연결 |

**원칙 3가지:**
1. **앱에서 막히는 것(계정·결제·입반)을 앞으로.** 전화 1위 출결은 뒤로 — 단, "회차/강좌 조회 + 문자 재발송"형 **조회 기능**으로 유지(AMS 상담내용 최빈어가 '주차·회차'였음).
2. **결제는 "이탈 막기"가 아니라 "도와주기".** 실사용자 결제완료 ~80%(정상). 가치 = 미납 회수 + 재시도 마찰 완화 + 외부 결제모듈 안내.
3. **모든 조회는 강좌 단위 키.** AMS 상담이 '특정 선생님 강좌' 단위로 일어남.

- `/classes`·`/player` 진입(학생) → 📋 출결·보강 · 📅 시간표 우선 노출.
- 학부모 모드(`/parents/*`) → 💳 · ✏️ · 🔄 우선.

## 4. 공통 규칙
- **막다른 길 금지**: 모든 카드 하단에 다음 행동. 마감반→대기, 결제대기→결제, 영상오류→계정.
- **조회는 강좌 단위 키**(AMS 상담내용 근거). 개인화는 본인확인 후(단 🔑 계정은 우회).
- **문자 재발송 버튼**: 보강자료·결제문자·증명서 등 "문자 다시 받기"를 곳곳에(AMS '문자' 최빈 3위).
- **결제 톤**: "이탈 막기" 아님 → "도와주기"(실제 완료 ~80% 정상).
- **핸드오프 표준**: 동의→접수번호→연결후안내(운영시간 분기) + 맥락칩 자동첨부.
- **문체**: –요체·따뜻·간결, 버튼=얻는 것, 마스킹, 미상은 [확인필요].
