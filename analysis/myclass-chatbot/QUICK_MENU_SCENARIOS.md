# 마이클래스 챗봇 — 빠른 메뉴 · 시나리오 (v2, 데이터 정밀 보완)

> **도출 경로**: "학생/학부모가 마이클래스 웹/앱을 쓰면서 **가장 궁금해할 것**" → 데이터로 추정 → 빠른 메뉴 → 메뉴별 대화 시나리오.
> **근거 3소스**: **GA4 라이브**(앱에서 지금 어디 있나·페이지뷰) · **AMS 상담 42.4만**(실제 무엇을 묻나·중분류 99종) · **카카오 1.6만**(디지털 인텐트). 상세 수치는 `DATA_ANALYSIS.md`.
> **v2 = 8개 메뉴를 페이지접속수(GA4) × 상담내역(AMS) 결합 분석으로 노드 단위 정밀화 + 능동 알림 레이어 신설.** (v1 대비 변경점은 §0)

## 3. 능동 알림 레이어 (신설) 🔔

> **메뉴가 아니라 트리거다.** 사용자가 묻기 전에 챗봇이 먼저 띄우는 레이어.
> **근거**: GA4 공지·알림 페이지뷰 **129,482**(`/announcements` 79,047 + `/notifications` 38,305) — 알림 보러 들어오는 행동이 이미 존재(뷰≈유저). 이를 **수동 조회 → 능동 푸시**로 전환해 결제 이탈·결석 누락·대기 충원 놓침을 선제 차단.

### 트리거 표 (이벤트 → 메시지 → 동의·빈도)
| # | 이벤트(소스) | 봇 메시지(예시) | 다음액션 | 동의·빈도 | Tier |
|---|---|---|---|---|---|
| N1 | **결석 처리됨**(출결 DB, 27,597) | "오늘 ○○ 수업 결석 처리됐어요. 보강 신청할 수 있어요" | [동영상 보강 신청][결석 사유 신고] | 출결알림 · 발생 시 1회 | T2 |
| N2 | **미납 발생/임박**(수납 DB, 8,954·이탈 61%) | "7월 수강료 미납이 있어요. 납부 기한 D-2" | [지금 결제하기][결제문자 다시] | 납부알림 · D-3·D-1·D-day 최대 3회 | T2 |
| N3 | **결제 미완료 이탈**(`/inbound/payment` 진입 후 미완료) | "결제가 끝나지 않았어요. 이어서 진행할까요?" | [결제 이어하기][도움 필요해요] | 납부알림 · 1h·24h 최대 2회 | T2 |
| N4 | **대기 충원 발생**(대기 DB, 7,258) | "대기 중인 ○○ 강좌에 자리가 났어요! 마감 전 등록하세요" | [지금 등록][대기 유지] | 대기알림 · 충원 즉시 1회(야간 허용) | T2 |
| N5 | **보강 영상 오픈**((L)복습 7,890·player 3.6만) | "어제 수업 보강 영상이 열렸어요. 7일간 시청 가능" | [지금 보기][나중에] | 학습알림 · 오픈 시 1회 | T1 |
| N6 | **결석 예정 마감 임박**(결석예정 23,501) | "내일 ○○ 수업 결석 예정 신고 마감이에요" | [결석 예정 신고][정상 출석] | 출결알림 · 마감 전 1회 | T2 |
| N7 | **교재 배송 상태 변경**((L)배송 3,203) | "주문하신 교재가 배송 출발했어요(송장 ****1234)" | [배송 추적] | 배송알림 · 상태변경 시 1회 | T2 |
| N8 | **설명회·컨설팅 리마인드**(예약 5,454) | "내일 14시 컨설팅 예약이 있어요" | [일정 보기][변경·취소] | 예약알림 · D-1·당일 최대 2회 | T2 |
| N9 | **공지·중요 안내**(`/announcements` 7.9만) | "[중요] 6/20 휴강 안내가 있어요" | [공지 보기] | 공지알림 · 중요도 high만 | T1 |

> **우선순위(가치순)**: N2·N3(결제, 이탈 61% 손실 차단) > N4(대기 충원, 시간 민감) > N1·N6(출결) > 나머지.
> **MVP 권장 3종: N2(미납) · N4(대기 충원) · N1(결석 처리).**

### 동의·운영 규칙
- **옵트인 우선**: 알림 종류별 on/off. 첫 능동알림 직전 1회 동의 수집.
  - 기본 ON 권장: 납부·출결·대기 충원·공지(high만). 기본 OFF: 학습(빈도 높음)·배송·예약(옵트인).
- **빈도 캡**: 1인/1일 최대 3건 · 동일 이벤트 24h 1회 · **야간(21–08시) 발송 금지**(N4 충원만 예외).
- **채널**: 인앱 챗봇 말풍선 기본 + 옵트인 시 푸시/문자 미러. 마스킹 유지. 같은 건 중복 발송 방지(상태키 1회).
- **[확인필요]**: ① 실시간 이벤트 소스(출결·수납·대기 DB webhook/polling) ② 푸시·문자 발송 인프라 ③ 미성년 데이터 법정대리인 동의 요건.

## 4. 메뉴별 정밀 시나리오 (대화 플로우)

표기: `봇:` 발화 · `[옵션]` 빠른답변 · `<카드(구성·API)>` · `→` 분기 · **Tier**(T1 즉답 / T2 개인화조회 / T3 핸드오프) · **라우팅**(auto/disamb/human).

### 0. 온보딩
```
스플래시(1.7s) → 봇: "안녕하세요 😊 안전한 상담을 위해 학생을 확인할게요."
[본인확인] 학생 이름 + 학부모 연락처 뒷 4자리

근거: form_submit 15.3만(폼 마찰) → 입력 2필드만. 개인데이터 조회 전제라 본인확인 유지.

   본인확인 게이트에 또 막히는 막다른 길 방지. 미인증 시 비개인화 가이드(T1)만 제공.
```

## 5. 시나리오 공통 규칙
- **막다른 길 금지**: 모든 카드 하단에 다음 행동(또는 처음으로/상담원). 마감반→대기, 결제대기→결제, 영상 오류→계정으로 항상 연결.
- **개인화는 본인확인 후**: 미인증 조회 시 잠금 + 본인확인 유도. **단, 계정·로그인 블록은 우회 허용**(가이드만).
- **능동 진입**: `page_path`로 빠른메뉴 선로딩(§2) + 능동 알림 레이어(§3).
- **핸드오프 표준**: 동의 → 접수번호 → 연결 후 안내(운영시간 분기). 전달은 최소 식별 + 맥락칩 자동 첨부.
- **Tier/라우팅**: T1 즉답(auto) · T2 개인화조회(본인확인 후 auto) · T3 핸드오프(human). 분류 혼동쌍은 1-step 명확화.
- **문체**: –요체·따뜻·간결. 버튼 = 사용자가 얻는 것(결제하기/보강 신청/연결하기). 마스킹 항상.
