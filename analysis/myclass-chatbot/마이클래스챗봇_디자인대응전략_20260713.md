## 이슈3 — 로그인 화면 "로그인 문제 해결" 링크

**왜 필요한가**: 챗봇은 로그인된 앱 안에서만 동작한다. 그런데 카카오 문의 중 가장 큰 덩어리(계정·로그인 관련, 44.5%[측정])는 사용자가 로그인 전이거나 로그인이 안 되는 상태에서 생긴다. 챗봇이 아무리 잘 만들어져도 이 사용자들은 애초에 챗봇에 닿지 못한다. 그래서 로그인 화면(로그인 전, 인증 불필요 구간)에 별도 안내 동선이 있어야 한다.

**디자인 확정 내용(JIRA 이슈3 초안 기준)**:
- 로그인 랜딩 페이지(재원생 전용)의 로그인 버튼 아래에 "로그인 문제 해결" 링크 노출.
- 클릭 시 안내 모달: 통합회원 안내(아이디=가입 이메일), 아이디 찾기/비밀번호 재설정 안내, 로그인 후 정보 안 보일 때 조치(재로그인, 학원 등록 정보 연동).
- 모달 하단 버튼: 아이디 찾기, 비밀번호 재설정.
- 반응형 3뷰(데스크탑/태블릿/모바일) 전부 지원.

**내가 추가로 미는 지점**: 모달 끝에 문의하기/상담 연결 경로를 넣자는 것. 계정·번호가 실제로 꼬인 경우는 아이디 찾기·비밀번호 재설정만으로는 안 풀리고, 로그인 전이라 챗봇도 못 쓰는 상태라 막다른 화면이 될 수 있다. 로그인 화면에 이미 카카오 채널 진입 동선이 있으면 생략 가능 — **QA 때 이 부분이 실제로 있는지 확인 필요.**

**★ 실측 결과(2026-07-13, dev+Figma 대조) — 스펙과 실제가 다름**:
- dev-myclass.sdij.com/classes에 접속하면 로그인 화면(dev-id.sdijon.com, 시대인재 통합로그인)으로 넘어가는데, **하단에 "가입/로그인에 문제가 있나요?" 링크가 실제로 존재한다.**
- 그런데 이 링크는 **모달이 아니라 그냥 다른 페이지(`dev-id.sdijon.com/faq?category=로그인/로그아웃`)로 이동하는 일반 링크**다. 스펙(클릭 시 안내 모달)과 다르다.
- **Figma `offplatform_챗봇` 파일의 1032:54(MYCLASS_챗봇) 페이지 전체를 뒤져봐도 로그인·아이디·비밀번호·모달 관련 프레임이 하나도 없다.** 즉 이슈3 모달 디자인은 사용자가 준 이 Figma 링크 안에는 없다 — 로그인 화면은 챗봇과 다른 화면(다른 파일이거나 다른 팀 소관)이라 별도로 존재할 가능성이 높다.
- **판단 필요**: (a) 이슈3이 아직 스펙대로 반영 전이라 지금 보이는 링크는 임시/기존 동선이거나, (b) 모달 대신 별도 페이지 이동으로 최종 결정이 바뀌었거나, (c) 진짜 모달 화면은 다른 dev 경로/Figma 파일에 있어서 이번엔 못 찾은 것 중 하나. **어느 쪽인지는 로그인 화면 Figma 파일 링크를 알려주면 확인 가능.**
- `dev-id.sdijon.com/faq...` 페이지 내용 확인은 브라우저 도구가 "확인된 적 없는 도메인"이라며 막아서 못 했다. 이 도메인이 맞다고 확인해 주면 이어서 본다.

## 이슈4 — 챗봇 FAQ 기능 추가

**왜 필요한가**: 현재 앱 FAQ는 카카오 채널 기준 수요가 낮은 주제(영상 재생 4.9%, 결제 할부 0.1%)에 쏠려 있다. 실제 수요는 계정·로그인(44.5%)과 절차 문의(라이브 신청 14.6%, 환불 11.0% 등)에 있다. FAQ 추가안 18개 항목은 이 수요 데이터로 우선순위를 잡았다.

**디자인 확정 내용**:
- 챗봇 홈 메뉴에 "자주 묻는 질문" 타일 추가 → FAQ 화면 진입.
- 상단 탭: 전체 / 계정·로그인 / 수강·대기·보강 / 앱·재생 / 결제·환불 / 기타. 기본은 전체, 탭 선택 시 해당 카테고리만 필터.
- 항목은 질문 클릭 시 답변이 펼쳐지는 아코디언.
- 콘텐츠 = FAQ 추가안 18항목(수요 순: 자녀 정보 안 보임 23.6%, 로그인 안 됨 20.7%, 라이브 신청 14.6%, 앱 설치/업데이트 13.7% 순).
- 개인 데이터가 필요한 질문은 "로그인 후 앱에서 확인" 안내로 처리(FAQ는 정적 안내만).
- 반응형 3뷰 지원.

**★ 실측 결과(2026-07-13, Figma 대조)**:
- Figma에 실제 FAQ 화면이 있다: node `1767:1519`("[Web-Mobile] 자주 묻는 질문", 400×1024), 경로는 1032:54 → "Flow-0. 인/아웃트로"(1362:506) → "Greeting section" 하위.
- 스크린샷으로 직접 확인: 검색창("궁금하신 내용을 검색해 주세요") + 탭바(계정·로그인 / 수강·대기·보강 / 앱·재생 / 결제·환불 / 기...) + 아코디언 10개 항목. 첫 항목("자녀(제) 정보가 안 보여요")은 펼쳐진 상태로 답변까지 보인다.
- **확인해볼 점**: 이 화면에서 "전체" 탭이 보이지 않았다(탭바가 가로로 더 있어서 잘렸을 수도 있음). 또 펼쳐진 목록 안에 "라이브 신청", "환불 규정"처럼 계정·로그인이 아닌 항목도 섞여 있어, 지금 활성 탭이 "전체"인지 "계정·로그인"인지 화면만으로는 확실치 않다. **탭 필터가 스펙대로(카테고리 선택 시 그 항목만) 동작하는지는 dev 화면에서 직접 눌러봐야 확정된다** — 이건 로그인 뒤라 이번엔 못 봤다.
- 답변 문구는 `FAQ_최종정리본.md`보다 조금 더 자세하다(예: "번호가 어긋난 경우 이미 등록된 번호 안내 확인 또는 상담 연결" 문구가 Figma엔 있고 md 요약엔 없음). 콘텐츠가 업데이트된 것으로 보이니 **최신 문구는 Figma 기준으로 보는 게 안전.**

**완료 조건(QA 체크리스트)**:
- [ ] 홈 타일 → FAQ 진입 정상
- [ ] 탭 선택 시 카테고리 필터 정상(전체는 전부 노출) → **위 실측에서 활성 탭·필터 동작을 확정 못함, dev 로그인 후 직접 확인 필요**
- [ ] 18개 항목·답변 오탈자/누락 없이 정확히 노출
- [ ] 게시 전 확인: 답변 속 앱 메뉴 경로(전체메뉴 > 내 정보 > 학원 등록 정보 연동 등)가 실제 화면과 일치하는지, 지점 전화번호가 채워졌는지

## 오픈 전략과의 연결

이슈3·4는 단독 기능이 아니라 **MYCLASS 챗봇 1차 조건부 오픈**(`마이클래스챗봇_오픈여부_결정메모.md`) 패키지의 일부다.

- 1차 오픈 권고 = 조회 챗봇(출결·납부·시간표·전반) + 계정·번호 매칭 수정을 **함께** 여는 것. 조회만 열면 카카오 문의의 약 12%[추정, 표본 162건]만 해결되고, 가장 큰 문제(계정 39%[측정, 6월 기준] / 44.5%[측정, 전체기간 기준])는 그대로 남는다.
- 이슈3(로그인 화면 안내)은 계정 매칭 수정이 완전히 배포되기 전에도, **로그인 전 단계에서 사용자를 막다른 길에 두지 않는 최소 조치**다. 이슈4(FAQ)는 로그인 전후 모두에서 절차성 문의를 셀프서비스로 돌린다.
- 즉 이 두 건이 QA를 통과해야 "1차 오픈 조건부 승인" 요건(론칭 블로커 0건 + 경미 수정 반영)이 채워진다.
