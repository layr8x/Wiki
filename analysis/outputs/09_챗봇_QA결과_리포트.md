# 마이클래스 도우미(재원생 챗봇) — 1차 QA 결과 리포트

> **검수일 2026-06-30 · 대상**: dev 환경 챗봇(`dev-myclass.sdij.com`) · **범위**: 1차(조회) 4개 메뉴 전 화면 직접 검수.
> **방식**: 4개 메뉴를 모두 직접 눌러 본 것만 기록. 데이터 부재로 못 띄운 화면은 '확인불가'.

## 한눈에 (3줄)
- **론칭 블로커 0** — 막을 만한 치명 이슈 없음.
- **1차 범위 준수 확인** — 챗봇 내 직접 처리(신청·변경·결제) 없음. 납부하기=외부 결제화면 연결, 처리성 문의=상담 연결.
- **경미·중 수정 5건** + 재검수 필요 3건(데이터 부재).

| **1차 범위 준수** | **준수** — 납부하기=결제화면 연결, 반변경·보강=상담 연결, 챗봇 내 실행 없음 |
| 수정 권고 | 경미·중 **5건** |
| 재검수 필요 | **3건** (계정/날짜 데이터 부재로 미확인) |

## 3. 수정 권고 (중요도순) — 론칭 전

| # | 항목 | 구분 | 담당 |
|---|---|---|---|
| 1 | **빈 화면 만족도 미노출** — 오늘 수업없음·타반보강 없음·추가영상 없음·결제내역 없음 4곳에서 만족도가 떠 규칙 위반 | 콘텐츠·로직 | 기획·프론트 |
| 2 | **전체 회차 일정** — "전체 N회 중 M회차 진행 중" 문구 추가 + 회차 정렬·15회차 중복 점검 | 콘텐츠+데이터 | 기획·개발팀 |
| 3 | **내 시간표 수업시간 빈칸**("월 /") — 시간 표기 누락 | 데이터·레이아웃 | 개발팀 |
| 4 | **전반 첫 안내문** "어떤 강좌로 전반을 원하시나요?" → 자연스러운 표현으로 | 콘텐츠 | 기획 |
| 5 | **납부기한 표기 통일** — 챗봇 12/26 ↔ 결제페이지 25.12.26 | 콘텐츠 | 프론트 |

> 참고: 위 1·4·5는 프로토타입(설계 정본)이 이미 올바른 동작을 보이므로, **프로토타입 기준으로 맞추면** 됩니다. (예: 프로토타입은 빈 화면에 만족도 미노출)

## 4. 재검수 필요 (이번 계정·날짜로 데이터 부재 → 미확인)

| 화면 | 사유 |
|---|---|
| 오늘 출석 '있는' 경우의 출결상태 표기 | 검수일 오늘 수업 없음 |
| 타반보강 '일정 있음' 형식 | 가능 일정 데이터 없음 |
| 동영상 보강 시청기한·N분 제공 형식 | '영상준비중' 상태 |

→ **수업이 있는 계정/날짜로 1회 추가 검수** 권장.

## 5. 론칭 준비도

```
개발 ✅ 완료   검수 ✅ 통과(블로커 0)   1차 범위 ✅ 준수
수정 ⏳ 경미 5건    재검수 ⏳ 3건    론칭일 ⏳ 〔개발팀 협의〕
```

**결론**: 경미 수정 5건 반영 + 수업 있는 계정 재검수 후 **1차 론칭 가능**.
