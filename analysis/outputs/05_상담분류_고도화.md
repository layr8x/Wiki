# 상담분류 고도화 — '기타' 28%를 LLM 재분류로 낮추기

> **3줄 요약**
> 1. 지금 분류는 **'기타'가 28.3%**(시대인재C는 **45.5%**)나 됩니다 — 분류가 사실상 "이건 모르겠다"로 처리되는 비율이 너무 높아, 채널별 문의 진단이 흐려집니다.
> 2. 실측으로 들여다보니 '기타' 2,038건 중 **약 30%(605건)는 환불·계정·교재 등 명확한 키워드가 들어 있는데도** '기타'로 빠진 케이스 — **LLM 재분류로 충분히 제자리로 돌릴 수 있습니다.**
> 3. 현 분류기는 신뢰도가 **0.70(키워드 맞음) / 0.30(못 맞춤=기타)** 두 값뿐인 단순 규칙 방식. LLM few-shot 분류 + 신뢰도 임계로 **기타를 28% → 12~18%(추정)** 까지 낮추는 게 목표입니다.

## 0. 한눈에 (비개발자용)

문의를 자동으로 분류하는 지금의 기계는 **"미리 정해둔 단어가 들어 있으면 그 칸, 없으면 무조건 '기타'"** 라는 단순한 규칙입니다. 마치 우편물을 "주소에 '대치'가 있으면 대치함, 없으면 전부 미분류함"에 넣는 것과 같습니다.

그래서 학부모가 "그거 환불 좀요"처럼 **표현을 살짝 바꾸면** 규칙이 못 알아듣고 전부 '기타'로 떨어집니다. '기타'가 28%나 되는 건 진짜로 분류 불가한 게 아니라, **규칙이 못 잡은 것**이 섞여 있다는 뜻입니다.

LLM(문맥을 이해하는 AI)은 단어가 아니라 **뜻**을 보므로, "그거 환불 좀요"도 환불로 정확히 넣습니다. 이 문서는 그게 실제로 가능하다는 걸 데이터로 보여주고, 방법·비용·검증법을 정리합니다.

## 2. '기타' 28%를 뜯어보기 — 정말 분류 불가한가?

'기타' 2,038건의 마지막 메시지를 키워드로 훑어본 실측 결과:

| '기타' 안의 실제 단서 | 건수 | 비중 | 재분류 가능? |
|---|---:|---:|---|
| 단순 응답/인사 ("넵·감사·확인·네") | 1,082 | 53.1% | ✗ (진짜 기타 — 의도 없음) |
| 단서 불명(짧거나 맥락 필요) | 455 | 22.3% | △ (LLM이 문맥으로 일부 회수) |
| **계정·로그인·앱 키워드 포함** | 150 | 7.4% | ✓ |
| **교재·배송 키워드 포함** | 126 | 6.2% | ✓ |
| **환불·결제 키워드 포함** | 100 | 4.9% | ✓ |
| **입반·등록 키워드 포함** | 87 | 4.3% | ✓ |
| **수업·출결 키워드 포함** | 38 | 1.9% | ✓ |

### 결론 (실측 기반)
- **명확히 회수 가능 = 501건(24.6%)** — 키워드가 버젓이 있는데 규칙이 놓친 것.
- **문맥 회수 추가 가능 = 단서불명 455건의 일부** — LLM이 대화 흐름을 보면 추가로 분류됨.
- **진짜 '기타' = 1,082건(53%)** — "넵/감사" 같은 의도 없는 응답. 이건 그대로 둬야 맞음.

> **즉 '기타' 28% 중 절반은 정당하고, 나머지 절반은 분류기를 고치면 줄어듭니다.**

## 3. 재분류 매핑 예시 (실측 샘플, ≤5건 · PII 마스킹)

'기타'로 빠졌지만 명확한 단서가 있는 대화를 무작위 추출해, **현 13종 체계 어디로 갈지** 매핑한 예시입니다. (원문은 의미만 요약·추가 마스킹)

| # | '기타' 대화의 요지(마스킹·요약) | 현재 | LLM 재분류 → | 근거 |
|---|---|---|---|---|
| 1 | "[앱] 접속 시 오류가 계속 떠요" | 기타(0.30) | **계정·로그인·앱** | '접속/오류' = 명백한 앱 문제 |
| 2 | "비밀번호 [재설정] 안내 부탁드립니다" | 기타(0.30) | **계정·로그인·앱** | 비밀번호 = 계정 영역 |
| 3 | "[아이디] 관련 문의요" (짧은 문장) | 기타(0.30) | **계정·로그인·앱** | 아이디 키워드 |
| 4 | "결제한 거 [환불] 가능한가요" | 기타(0.30) | **환불** | 환불 의도 명확 |
| 5 | "[로그인] 화면이 안 넘어가요" | 기타(0.30) | **계정·로그인·앱** | 로그인 차단 |

> 5건 모두 신뢰도 0.30(='기타')였으나, 사람이 보면 즉시 분류 가능. LLM도 동일하게 분류합니다. 이게 "회수 가능"의 실체입니다.

## 4. 방법 — LLM few-shot 재분류 + 신뢰도 임계

### 4-1. 동작 흐름

```
'기타'(또는 신뢰도 0.30) 대화만 골라냄
   → 대화 마지막 N개 메시지를 LLM에 입력
   → "아래 13개 카테고리 중 하나로 분류 + 0~1 신뢰도 출력" 지시
   → 신뢰도 ≥ 0.6 이면 새 카테고리로 교체 / 미만이면 '기타' 유지
   → 사람 검수 큐로 일부 샘플링
```

### 4-2. few-shot 프롬프트 골격 (개념)

- **시스템**: "너는 학원 상담 분류기다. 카테고리 13종: 계정·로그인·앱 / 환불 / 라이브 / 교재·배송 / 입반·등록 / 미납·결제 / 대기 / 출결·보강 / 통합회원 / 시간표·수업 / 퇴원·취소 / 설명회·컨설팅 / 기타. 의도가 없으면(단순 인사·확인) '기타'로 둬라."
- **예시(few-shot)** = §3 같은 (대화 요지 → 정답) 쌍 6~10개. **이미 만든 Q-A 데이터셋**(→ `04_LLM_데이터셋_스펙.md`)에서 고신뢰 라벨을 본보기로 씁니다.
- **출력**: `{"category": "...", "confidence": 0.0~1.0, "reason": "..."}` JSON 고정.

### 4-3. 신뢰도 임계(threshold)의 역할
- LLM도 애매하면 낮은 신뢰도를 냅니다. **임계 0.6 미만은 '기타'로 보존** → 억지 분류로 인한 오염 방지.
- 임계는 §6 검증에서 **사람 검수 정확도가 95% 넘는 지점**으로 조정합니다.

## 6. 비용·검증법

### 6-1. 비용 (추정)
- 재분류 대상 = '기타' **2,038건** (1회 일괄). 대화당 짧은 텍스트 몇 줄.
- LLM 호출 1건당 입력 수백 토큰 수준 → **전량 1회 재분류 비용은 소액**(수 달러~십수 달러 추정). 신규 유입분만 매일 돌리면 일 비용은 무시할 수준.
- 정확한 단가는 사용 모델에 따라 다르므로 **PoC(소규모 시범) 후 실측**합니다. (모델·단가는 별도 확인)

### 6-2. 검증법 (반드시 통과)
1. **골든셋 채점**: '기타' 중 사람이 정답을 단 **200건 검수셋**을 만들고, LLM 재분류 정확도를 측정. **목표 ≥ 95%.**
2. **임계 튜닝**: 신뢰도 임계를 0.5→0.7로 올려가며 (정확도 ↔ 회수율) 곡선을 그려 최적점 선택.
3. **오분류 감사**: 새로 '환불'로 바뀐 건 중 무작위 표본을 재검수 — **억지 분류로 다른 칸을 오염시키지 않는지** 확인.
4. **회귀 방지**: 기존 0.70 분류건은 건드리지 않고, **'기타'/0.30 건만** 대상으로 제한.

검증 추출 SQL(검수셋 만들기):

```sql
-- '기타'에서 사람 검수용 표본 추출 (라벨 비워 사람이 채움)
SELECT chat_id, profile_id, last_message_len
FROM (
  SELECT chat_id, profile_id, length(last_message) AS last_message_len
  FROM kakao_partner_chats
  WHERE category = '기타' AND last_message IS NOT NULL
) t
ORDER BY random() LIMIT 200;
```

## 8. 실측 재분류 데모 + ★ 추가 발견 (2026-06-30 직접 실행)

'기타' 대화 **무작위 15건**의 마지막 메시지를 실제로 뽑아 사람(=LLM)이 재분류해 봤습니다(원문은 마스킹·요약).

| 마지막 메시지 요지 | 현재 | 재분류 판단 |
|---|---|---|
| "다시 제휴학원 연동 후 조회해보세요" | 기타 | **계정·로그인·앱** (연동·조회) |
| "조회되도록 수정했습니다, 메뉴 들어가 조회를" | 기타 | **계정·로그인·앱** |
| "재입고 후 발송될 예정입니다" | 기타 | **교재·배송** |
| "커리큘럼·수업관련은 각 지점 유선 문의" | 기타 | **시간표·수업** |
| "현재 판매가 마감되었습니다" | 기타 | 입반·등록 (낮은 신뢰) |
| "네 감사합니다 / 상담 종료하겠습니다 / 무엇을 도와드릴까요" (8건) | 기타 | **기타 유지**(진짜 종료·인사) |

→ 15건 중 **약 6건(40%) 재분류 가능**, 9건은 정당한 '기타'. §2의 추정(절반 회수)과 일치.

### ★ 추가 발견 — '기타'가 많은 진짜 이유: "마지막 메시지 = 상담원 종료멘트"
재분류 불가였던 9건 대부분이 **상담원의 끝인사**("감사합니다", "종료하겠습니다", "무엇을 도와드릴까요")였습니다. 즉 현재 분류가 **대화의 마지막 메시지(주로 상담원 마무리)** 를 보기 때문에 키워드가 없어 '기타'로 떨어지는 구조적 원인이 큽니다.

> **개선 핵심**: 분류 입력을 `last_message`(상담원 종료멘트)가 아니라 **사용자(user)의 질문 메시지**(대화 첫 user 발화 또는 user 발화 묶음)로 바꾸면, LLM 재분류 없이도 '기타'가 크게 줄어듭니다. LLM 재분류는 그 위에 얹는 2차 정밀화입니다. → §7 실행 순서의 0단계로 "분류 입력을 user 질문으로 교체"를 추가 권장.
