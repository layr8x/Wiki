# 계정·로그인 도움, 어디에 둘 것인가 — 배치 제안서

> **3줄 요약**
> 1. 디지털 채널 최대 수요는 **계정·로그인·앱**(카카오 전체 36.2%, 마이클래스·라이브는 각 약 56%)인데, 이 문의는 **"로그인 전"** 에 터진다.
> 2. 그런데 인앱 챗봇은 **"로그인 후" 화면에 살아서**, 정작 이 수요를 가진 사용자에게는 **닿지 못한다**(구조적 사각지대).
> 3. → 계정·로그인 도움을 **① 로그인 화면 셀프 해결 안내 ② 카카오 채널 자동응답 ③ 비밀번호·앱오류 가이드**에 배치하자. 정책 수치는 `〔확인〕` 표시.

> **읽는 분께**: 이 문서는 "챗봇을 더 키우자"가 아니라 **"챗봇이 닿을 수 없는 수요를 다른 자리에서 받자"** 는 제안입니다. 인앱 챗봇 기획(전화 출결·결제 정조준)과 **충돌하지 않고 보완**합니다.

## 1. 문제 — 가장 큰 디지털 수요인데, 우리 도구가 못 닿는다

### 1-1. 데이터 근거 — 디지털 채널 1위가 계정·로그인

| 채널 | 계정·로그인·앱 비중 | 막대 |
|---|---:|---|
| 마이클래스 | **56.5%** | ████████████████████████████ |
| 라이브 | **56.2%** | ████████████████████████████ |
| 시대인재C | 13.6% | ███████ |
| 카카오 전체 | **36.2%** | — |
| (참고) 전화 채널 | 0.2% | ▏ |

*(막대 1칸 ≈ 2%. 출처: 카카오 비즈채팅 라이브 7,291대화 / 85,936메시지, 자동 분류 적용 98.7%, 2026-06-30 실측.)*

- 앱을 직접 쓰는 마이클래스·라이브에서 **문의 2건 중 1건 이상이 "앱에 못 들어감"**.
- 전화 채널엔 계정 문의가 **0.2%뿐** → 이건 **디지털에서만 폭발하는 수요**다. 카카오를 수집하지 않았으면 아예 못 봤을 사실.

### 1-2. 무엇이 막히나 (계정·로그인·앱 안에 묶이는 것들)

- 로그인 실패 / 아이디·비밀번호 분실
- 앱 오류·실행 안 됨·재설치
- 인증·본인확인 문제
- 가입·계정 전환

→ 공통점: **콘텐츠를 못 봐서가 아니라, 콘텐츠에 도달하기 전 단계에서 막힌다.**

## 2. 왜 인앱 챗봇으로는 못 잡나 — 구조적 사각지대

```
[사용자 상태]            [도움이 사는 곳]
로그인 전  ──(로그인 실패)──→  ???  ← 도움이 여기 없음 (사각지대)
   │
   ▼ (로그인 성공해야)
로그인 후  ──────────────→  인앱 챗봇 (출결·결제 등)
```

- 인앱 챗봇은 **로그인된 앱 안**에 산다.
- 계정·로그인 수요는 **로그인 전에 발생**한다 — 그 사용자는 애초에 앱에 못 들어와서 묻는 것이다.
- 따라서 **챗봇을 아무리 잘 만들어도 이 56%에는 닿지 못한다.**

> 비유: 가게 안에 아무리 좋은 안내데스크를 둬도, **문이 안 열려 못 들어온 손님**에게는 소용이 없다. 그 손님에게 필요한 건 **문 앞(로그인 화면)과 전화·카톡(가게 밖 채널)** 의 안내다.

이것이 마이클래스 챗봇 메뉴에서 '계정·앱'을 **일부러 뺀** 이유이기도 하다. 챗봇은 전화의 출결·보강·입반·결제에 집중하는 게 맞고, 계정·로그인은 **다른 자리**에서 받아야 한다.

## 3. 배치안 — 세 자리에 도움을 둔다

### 배치안 ① 로그인 화면 셀프 해결 안내 (로그인 전)

로그인 화면 자체에 **"못 들어가세요?"** 셀프 해결 동선을 노출.

| 요소 | 내용 | 비고 |
|---|---|---|
| 진입점 | 로그인 버튼 하단 "로그인이 안 되나요?" 링크 | 항상 노출 |
| 1차 자가 안내 | 아이디 찾기 / 비밀번호 재설정 / 앱 오류 해결 / 재설치 가이드 | 클릭형 셀프 |
| 실패 트리거 | 로그인 `〔확인〕회` 연속 실패 시 도움 안내 자동 노출 | 막힌 사용자 정조준 |
| 최후 동선 | 그래도 안 되면 → 카카오 채널 연결 버튼 | 배치안 ②로 연결 |

### 배치안 ② 카카오 채널 자동응답 (로그인 전, 가게 밖)

이미 계정·로그인 문의가 가장 많이 들어오는 **카카오 채널**에 자동응답 1차 대응을 둔다.

| 요소 | 내용 |
|---|---|
| 자동응답 키워드 | "로그인 안 됨 / 비밀번호 / 앱 오류 / 아이디" 등 |
| 1차 자동 답변 | 가장 빈번한 해결법을 즉시 카드형으로 제공 |
| 사람 연결 | 자동 답변으로 안 풀리면 상담원 연결 (현 운영 유지) |
| 우선순위 | 마이클래스·라이브 채널 우선 (계정 비중 56%) / 시대인재C는 환불·교재 위주로 별도 |

### 배치안 ③ 비밀번호·앱오류 가이드 (공통 콘텐츠)

①②가 공통으로 참조할 **표준 셀프 해결 가이드**를 만든다.

- 비밀번호 재설정 단계별 가이드
- 앱 오류·강제종료·재설치 가이드 (iOS / Android)
- 본인인증·가입 문제 FAQ
- → 로그인 화면·카카오 자동응답·기존 FAQ가 **같은 가이드를 재사용**(중복 관리 방지).

## 4. 기대 효과

| 효과 | 설명 | 측정 가능? |
|---|---|---|
| **사각지대 수요 흡수** | 인앱 챗봇이 못 닿던 계정·로그인(디지털 최대 수요)을 처음으로 셀프 해결로 전환 | ✅ |
| **카카오 상담원 부하 감소** | 가장 많이 들어오는 계정·로그인 문의를 자동응답이 1차로 받음 | ✅ |
| **앱 진입 성공률 상승** | 로그인 단계 이탈 사용자를 다시 안으로 들임 → 결제·수강 등 본 활동 연결 | ✅ |
| **채널별 맞춤 대응** | 마이클래스·라이브=로그인 / C=환불·교재로 자동응답을 분리 | ✅ |

> 효과의 크기(몇 %)는 **배포 전이므로 단정하지 않는다.** 아래 측정 설계로 배포 후 증명한다.

## 5. 측정법 — 어떻게 "줄었다"를 증명하나

배포 전이라 지금 추세를 효과로 귀속하지 않는다. 배포 후 **선행 → 결과** 순으로 측정한다.

| 단계 | 지표 | 데이터 출처 | 비고 |
|---|---|---|---|
| **선행** | 로그인 화면 도움 **클릭률**, 셀프 가이드 **완료율**, 카카오 자동응답 **해결율(사람 연결 전 종료)** | 로그인 화면 로그·카카오 채널 | 한 달 안에 바로 보임 |
| **선행** | 로그인 **재시도 성공률**(도움 노출 후 성공 비율) | 인증 로그 | 진입 회복 직접 신호 |
| **결과** | 카카오 **계정·로그인 문의 대화 수 감소** | 카카오 수집 DB(이미 구축됨) | Before/After |
| **결과** | 로그인 단계 **이탈률 감소** | GA4 | 동월 비교 |
| **보정** | 시즌(수강신청·기말)·앱 업데이트 영향 분리 | — | 자연 추세 대조 |

**대조군(효과 귀속 함정 회피)**

- 계정·로그인 문의가 둘 다 약 56%인 **마이클래스 vs 라이브**를 활용 → **한 채널 먼저 배포 → 다른 채널을 자연 대조군**으로 비교하면, 시즌·전사 변화와 도움 배치 효과를 분리할 수 있다.
- 카카오 수집 파이프라인이 이미 가동 중이라 **Before/After 데이터가 자동으로 쌓인다**(추가 수집 작업 불필요).

## 7. 한계 · 정직성

- 챗봇·도움 배치 모두 **미배포** → 효과 크기는 본 제안에 포함하지 않음(측정으로 증명).
- 카카오 `기타` 분류 비중이 높아(특히 시대인재C 45.5%) 계정·로그인 실제 비중은 **하한**일 수 있음 — 즉 수요는 보고치 이상일 가능성.
- 학생/학부모 발신자 세부 구분 필드 없음 → "누가" 막히는지는 채널 성격으로만 추정.
- 카카오는 대화/메시지 단위, 전화는 건 단위 → **채널 간 절대 건수 직접 비교 금지**, 채널 내 비중으로만 해석.
