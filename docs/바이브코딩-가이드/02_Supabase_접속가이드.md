# 바이브 코딩 실전 가이드 ③ Supabase

> **바이브 코딩 실전 가이드 시리즈**: ① 시작하기 · ② GitHub · **③ Supabase (이 문서)** · ④ Vercel

> 📌 **한 줄 요약**
> Supabase(슈파베이스)는 우리 서비스의 **"데이터 보관함(창고) + 로그인 관리사무소"** 입니다.
> 위키 가이드 글, 카카오 상담 데이터, 직원 로그인 계정, 그리고 뒤에서 자동으로 도는 작업들이 전부 여기 있습니다.
> 기획자는 주로 **저장된 데이터를 표처럼 조회**하게 됩니다.

---

## 1. Supabase가 뭔가요? (비유)

Supabase는 한마디로 **거대한 엑셀 창고 + 출입증 발급소**입니다.

- **데이터 보관** (창고): 상담 내용, 가이드 글, 조회 기록 등을 "표(테이블)" 형태로 보관. 엑셀 시트가 수백만 줄까지 커진 것이라고 보면 됩니다.
- **로그인 관리** (관리사무소): 누가 위키에 로그인할 수 있는지 계정·출입증을 발급·관리.
- **자동 작업** (창고 직원): "5분마다 카카오 상담 새로 수집", "매일 아침 요약 슬랙 발송" 같은 일을 사람 없이 자동으로 수행.

우리 프로젝트 이름은 **`sdij-wiki`** 이고, 데이터는 서울 지역 서버에 보관됩니다. (엔진은 PostgreSQL이라는, 은행권에서도 쓰는 튼튼한 데이터베이스입니다.)

---

## 2. 접속 준비 (처음 한 번만)

### 1단계. 계정 만들기
**https://supabase.com/dashboard 에서 GitHub 계정으로 로그인**하는 게 가장 간단합니다. (앞서 만든 GitHub 계정 재사용)

### 2단계. 조직(Organization)에 초대받기
Supabase는 "조직 > 프로젝트" 구조라, 우리 조직에 초대돼야 `sdij-wiki` 프로젝트가 보입니다.
- **관리자(사장님)에게 "제 Supabase 로그인 이메일은 OOO 입니다. 조직에 초대해 주세요" 요청**하세요.
- 초대 메일의 **`Accept`** 를 누르면 끝입니다.

> 관리자 참고: Supabase 대시보드 → Organization → Team → Invite. 기획자에겐 **`Read only`(읽기 전용)** 권한을 주면 데이터를 볼 수는 있어도 실수로 못 바꿔서 가장 안전합니다.

### 접속 확인
로그인 후 프로젝트 목록에서 **`sdij-wiki`** 를 클릭해 들어가지면 성공입니다.

## 3. 화면 둘러보기 (왼쪽 메뉴 지도)

프로젝트에 들어가면 왼쪽에 아이콘 메뉴가 있습니다. 기획자 기준으로 정리합니다.

| 메뉴 | 우리말 | 여기서 뭘 하나 |
|---|---|---|
| **Table Editor** | 표 편집기 | 데이터를 **엑셀처럼 표로 조회** (기획자 주 무대). 보기 위주 |
| **SQL Editor** | 명령 편집기 | 고급 조회. ⚠️ 명령을 잘못 실행하면 위험 → 기획자는 가급적 사용 안 함 |
| **Authentication** | 로그인 관리 | 위키에 로그인하는 **사용자 계정 목록** 확인 |
| **Edge Functions** | 자동 기능 | 카카오 수집·분류·알림 같은 **작은 자동 프로그램** 목록 |
| **Database** | 데이터베이스 | 표 구조·자동작업 예약(cron) 등 뼈대. 보기만 |
| **Logs / Reports** | 기록 / 통계 | 오류 기록, 사용량 그래프 확인 |

> 📷 (컨플루언스에 Table Editor 화면 캡처를 넣으면 이해가 빠릅니다.)

## 4. 기획자 실전: 이런 걸 하게 됩니다

### 실전 A. 저장된 데이터를 표로 조회하기
가장 많이 쓰는 기능입니다.

1. **왼쪽 `Table Editor`** 클릭
2. 가운데에서 볼 표(테이블)를 선택. 예:
   - `kakao_partner_chats` = 카카오 상담 "대화" 목록
   - `kakao_partner_messages` = 대화 안의 개별 "메시지"
   - `guides` = 위키에 올라간 가이드 글
3. 오른쪽에 엑셀처럼 내용이 뜹니다. 위쪽 **`Filter`(거르기)** 로 원하는 조건만 볼 수 있습니다.

> 💡 표는 **눈으로 보기만** 하세요. 칸을 더블클릭하면 수정 화면이 뜨는데, **값을 바꾸고 저장하지 마세요.** 실제 데이터가 바뀝니다.

### 실전 B. "상담이 얼마나 쌓였지?" 규모 확인
1. `Table Editor`에서 `kakao_partner_chats` 선택
2. 표 아래쪽 또는 상단에 **총 건수(row 수)** 가 표시됩니다.

### 실전 C. 위키 로그인 사용자 확인
1. **왼쪽 `Authentication`** 클릭 → `Users`
2. 가입·로그인한 계정 목록, 마지막 로그인 시각 등을 볼 수 있습니다.

### 실전 D. 자동 작업이 잘 도는지 확인
1. **`Edge Functions`** 에서 `kakao-collect`(수집)·`kakao-daily-summary`(일일 요약) 등 목록 확인
2. 각 기능을 클릭하면 최근 실행 기록·성공 여부를 볼 수 있습니다.

## 5. 절대 하지 말 것 (안전선)

| 하지 말 것 | 이유 |
|---|---|
| **표의 값을 바꾸고 저장 / 행 삭제(Delete row)** | 진짜 상담·가이드 데이터가 사라지거나 틀어집니다. 되돌리기 어렵습니다 |
| **`SQL Editor`에서 명령 실행** | 한 줄로 표 전체를 지울 수도 있는 강력한 도구입니다 |
| **`Settings`의 키(API Key)·비밀번호 복사해서 외부로 전송** | 이 키가 새면 남이 우리 데이터에 접근할 수 있습니다. 화면에 보여도 밖으로 내보내지 마세요 |
| **테이블·프로젝트 삭제(Delete)** | 서비스 전체가 멈춥니다 |

기획자는 **"표 조회 · 사용자 확인 · 자동작업 상태 보기"** 까지만 하면 안전합니다.

## 6. 용어 사전 (자주 나오는 말)

| 용어 | 쉬운 뜻 |
|---|---|
| 데이터베이스 (DB) | 데이터를 담는 거대한 창고. 우리는 PostgreSQL 사용 |
| 테이블 (Table) | 창고 안의 "표 한 장" (엑셀 시트 같은 것) |
| 행 (Row) / 열 (Column) | 표의 가로 한 줄(기록 하나) / 세로 항목(예: 이름, 날짜) |
| RLS (Row Level Security) | "누가 어떤 줄을 볼 수 있는지" 정하는 접근 규칙 (= 보안 잠금) |
| Edge Function | 필요할 때 도는 작은 자동 프로그램 (예: 카카오 수집) |
| cron (크론) | "매일 9시" 처럼 정해진 시각에 자동 실행하는 예약 |
| Migration (마이그레이션) | 창고 구조(표 모양)를 바꾸는 "설계도 갱신" |
| API Key (키) | 프로그램이 창고에 접근할 때 쓰는 비밀 열쇠. **절대 외부 유출 금지** |

## 7. (참고) 개발자·AI는 실제로 어떻게 연결하나

기획자는 대시보드 화면만으로 충분하지만, 뒤 원리를 짧게 적습니다. (안 읽으셔도 됩니다.)

1. 사이트(위키)와 자동 기능들은 **"주소(URL) + 키(Key)"** 한 쌍으로 Supabase 창고에 접속합니다.
2. 키는 두 종류입니다: 화면에 노출돼도 비교적 안전한 **공개용 키(anon key)** 와, 서버 뒤에서만 쓰는 **관리자 키(service key, 절대 유출 금지)**.
3. 이 값들은 코드에 직접 적지 않고 **환경변수(= 프로그램에 몰래 넣어두는 설정값)** 로 보관합니다. (GitHub·Vercel에 비밀로 저장)
4. 표 구조를 바꿀 땐 **마이그레이션 파일**(설계도 갱신 문서)을 GitHub에 남겨, 언제 왜 바꿨는지 추적합니다.

즉 기획자가 표에서 보는 데이터는, 이 연결을 통해 사이트·자동작업이 쌓아 둔 결과입니다.

## 8. 문제가 생기면

| 증상 | 이렇게 하세요 |
|---|---|
| 로그인은 됐는데 `sdij-wiki` 프로젝트가 안 보임 | 조직 초대 미수락 가능성. 관리자에게 재초대 요청 |
| 표를 잘못 건드린 것 같음 | **더 누르지 말고** 화면 캡처해서 즉시 개발자에게 문의 (빠를수록 복구 쉬움) |
| 키(비밀번호 같은 문자열)를 실수로 외부에 보냄 | 즉시 관리자·개발자에게 알림 → 키 재발급 필요 |

> 데이터는 회사의 자산입니다. 확신이 안 서면 **보기만 하고 손대지 않는 것**이 항상 정답입니다.
