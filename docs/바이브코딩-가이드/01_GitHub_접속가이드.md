# 바이브 코딩 실전 가이드 ② GitHub

> **바이브 코딩 실전 가이드 시리즈**: ① 시작하기 · **② GitHub (이 문서)** · ③ Supabase · ④ Vercel

> 📌 **한 줄 요약**
> GitHub(깃허브)는 **코드의 "구글 드라이브 + 변경 이력 장부"** 입니다.
> 바이브 코딩의 출발점: **본인 저장소를 하나 만들고, 거기에 AI 도구를 연결**하면 AI가 그 안에서 코드를 만들어 줍니다.
> 여러분은 AI가 만든 변경을 **검토 → 합치기(머지)** 하며 프로젝트를 키웁니다.

---

## 1. GitHub가 뭔가요? (비유)

문서를 여러 번 고치면 `기획서_최종.doc`, `기획서_최종_진짜.doc` 처럼 파일이 엉키죠. GitHub는 그 문제를 코드에서 완전히 해결합니다.

- **코드를 한 곳에 안전하게 보관** (구글 드라이브처럼)
- **모든 변경을 사진 찍듯 기록** (되돌리기 가능, "왜 바꿨는지"까지)
- **AI가 고친 것을 검토하고 합치는 관문** (바로 반영이 아니라, 확인 후 합침)

바이브 코딩에서 GitHub는 **"내 프로젝트가 사는 집이자, AI가 작업하는 작업대"** 입니다.

## 2. 본인 것 만들기 (처음 한 번만)

### 1단계. 계정 만들기
**https://github.com/signup 에서 회원가입** 합니다. 아이디·이메일·비밀번호만 있으면 됩니다.

### 2단계. 2단계 인증 켜기 (보안 필수)
- **Settings → Password and authentication → Two-factor authentication → Enable** 로 휴대폰 인증앱 설정. (비밀번호가 새도 계정을 지켜줍니다.)

### 3단계. 본인 저장소(Repository) 만들기
내 프로젝트가 살 집을 만듭니다.
1. 오른쪽 위 **`+` → `New repository`** 클릭
2. **Repository name**: 프로젝트 이름 (예: `my-first-app`)
3. **`Private`(비공개) 선택** 을 권장합니다. (연습·아이디어는 남에게 안 보이게)
4. **`Add a README file`** 체크 → **`Create repository`**

이제 `github.com/내아이디/my-first-app` 라는 나만의 저장소가 생겼습니다.

### 4단계. 바이브 코딩 도구 연결
AI가 이 저장소에서 작업하도록 연결합니다.
- **AI 코딩 도구**(예: Claude Code, Cursor 등)에 GitHub 계정으로 로그인하고, 방금 만든 저장소를 선택하면 됩니다.
- 그러면 여러분이 "이런 거 만들어줘"라고 말할 때 AI가 이 저장소 안에 코드를 만들어 넣습니다.

> 💡 저장소는 **아이디어마다 하나씩** 새로 만들면 깔끔합니다. 서로 안 섞이게요.

## 3. 화면 둘러보기 (상단 탭 지도)

본인 저장소에 들어가면 위쪽에 탭이 있습니다.

| 탭 | 우리말 | 여기서 뭘 하나 |
|---|---|---|
| **Code** | 코드 | 파일·폴더 보기, 문서 읽기, 간단한 직접 수정 |
| **Issues** | 이슈 | **할 일·아이디어·버그를 글로 등록**하고 정리 |
| **Pull requests** | 풀 리퀘스트(PR) | **AI가 만든 변경을 검토·합치기(머지)** |
| **Commits** | 커밋(변경 기록) | 언제 무엇이 왜 바뀌었는지 시간순 기록 |
| **Settings** | 설정 | 저장소 공개범위·삭제 등. 신중히 |

> 📷 (컨플루언스에 실제 화면 캡처를 넣으면 좋습니다: 저장소 첫 화면 + New repository 화면)

## 4. 실전: 바이브 코딩 한 바퀴 돌려보기

### 실전 A. 아이디어를 이슈로 적어두기
"뭘 만들지"를 글로 남겨 두면 AI에게 시키기도 쉽고 나중에 정리도 됩니다.
1. **Issues 탭 → 초록색 `New issue`** 클릭
2. 제목 + 본문에 "무엇을 / 왜 / 어떻게 되면 좋겠는지" 적기 → **`Submit new issue`**

### 실전 B. AI가 만든 변경 검토하고 합치기 (핵심)
바이브 코딩의 심장입니다. AI가 코드를 만들면 **PR(변경 검토 요청)** 이 올라옵니다. 여러분이 확인하고 **합칩니다(머지).**
1. **Pull requests 탭**에서 항목 클릭
2. 맨 위 설명으로 "무엇을 왜 바꿨는지" 파악
3. **`Files changed`(바뀐 파일) 탭**에서 실제 변경 확인 (빨강=지운 줄, 초록=추가한 줄)
4. 좋으면 **`Merge`(합치기)** 로 정본(`main`)에 반영. 고칠 게 있으면 코멘트로 "여기 이렇게 고쳐줘" 남겨 AI에게 다시 시키기

> 💡 **초안(Draft)** 은 아직 작업 중이라는 뜻. 다 됐으면 `Ready for review` 후 합칩니다.
> 💡 합치기는 보통 **`Squash and merge`**(여러 변경을 한 줄로 깔끔히) 를 쓰면 이력이 정돈됩니다.

### 실전 C. 문서·내용 직접 고치기 (가벼운 편집)
오타 같은 간단한 수정은 화면에서 바로.
1. Code 탭에서 파일 클릭 → 오른쪽 위 **연필 아이콘(✏️ Edit)**
2. 수정 후 **`Commit changes`**

> ⚠️ 코드 파일(`.js`, `.ts` 등)은 문법이 조금만 틀려도 작동이 멈칩니다. **코드 변경은 AI에게 시키고 여러분은 검토**하는 편이 안전합니다. 문서(`.md`)는 편하게 고쳐도 됩니다.

### 실전 D. "언제 뭐가 바뀌었지?" 이력 확인 · 되돌리기
- Code 탭 → 커밋 개수 클릭 → 시간 역순 변경 기록. 잘못된 변경은 **`Revert`(되돌리기)** 로 원복하거나, AI에게 "이 변경 되돌려줘" 요청.

---

## 5. 되돌리기 어려운 것 (주의)

대부분은 되돌릴 수 있지만, 아래는 신중히.

| 주의 대상 | 왜 |
|---|---|
| **`Settings → Delete this repository`** | 저장소가 통째로 사라짐 (되돌리기 매우 어려움) |
| **비밀값(키·비밀번호)이 담긴 파일을 올림** | 이력에 남아 유출. 올리기 전 AI에게 "비밀값 없나 확인해줘" |
| **저장소를 `Public`(공개)으로 바꾸기** | 아이디어·코드가 전 세계에 공개됨. 연습은 `Private` 유지 |

> 코드 변경은 대부분 **`Revert`** 로 원복되니 크게 겁낼 필요 없습니다. 정말 조심할 건 "삭제"와 "공개 전환"뿐입니다.

---

## 6. 용어 사전

| 용어 | 쉬운 뜻 |
|---|---|
| 저장소 (Repository, 레포) | 한 프로젝트 코드가 통째로 든 폴더(= 내 프로젝트의 집) |
| 커밋 (Commit) | 변경을 "사진 한 장 찍어 저장"한 단위 |
| 브랜치 (Branch) | 원본을 안 건드리고 작업하는 "사본 공간". `main`이 정본 |
| PR (Pull Request) | "이렇게 바꿨으니 정본에 합쳐도 될지" 검토 요청 |
| 머지 (Merge) | 검토 끝난 PR을 정본에 실제로 합치는 것 |
| 이슈 (Issue) | 할 일·아이디어·버그를 적어 두는 글 |
| Private / Public | 비공개 / 공개. 연습은 Private 권장 |

## 7. 연결 원리 (AI와 함께 실제로 어떻게 도나)

1. 바이브 코딩 AI는 여러분의 GitHub 저장소를 작업공간으로 삼습니다.
2. 여러분 지시대로 코드를 만든 뒤 **커밋(저장)** 하고 GitHub로 **푸시(올리기)** 합니다.
3. 보통 곧바로 정본에 넣지 않고 **PR로 만들어** 여러분의 검토를 기다립니다.
4. 여러분이 **머지** 하면 정본(`main`)에 반영되고, 이어서 Vercel 자동 배포(웹사이트가 있으면)로 연결됩니다.

즉 **"AI가 만들고 → 내가 검토·승인 → 정본 반영"** 의 관문이 GitHub입니다.

---

## 8. 문제가 생기면

| 증상 | 이렇게 하세요 |
|---|---|
| 저장소를 못 찾겠음 | 오른쪽 위 프로필 → `Your repositories`에서 목록 확인 |
| 합치기(Merge) 버튼이 회색 | 초안(Draft)이거나 검사 중. `Ready for review`로 바꾸고 대기 |
| 잘못 합친 것 같음 | 대부분 **`Revert`** 로 원복 가능. AI에게 "이 PR revert 해줘" 요청 |
| 크게 잘못 누른 것 같음 | 더 누르지 말고 화면 캡처 후 AI에게 상황 설명 |
