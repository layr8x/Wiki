# 바이브 코딩 실전 가이드 ① 시작하기

> **바이브 코딩 실전 가이드 시리즈** (개발을 몰라도, AI와 함께 내 아이디어를 직접 만들기)
> ① 시작하기 (이 문서) · ② GitHub · ③ Supabase · ④ Vercel

> 📌 **한 줄 요약**
> 이 가이드는 **각자 본인 아이디어를 바이브 코딩으로 직접 만들어 보며 배우기 위한 교재**입니다.
> 그러려면 코드를 담을 **GitHub**, 데이터를 담을 **Supabase**, 사이트를 띄울 **Vercel** 세 곳을 **본인 것으로(무료로) 세팅**할 줄 알아야 합니다.
> 이 문서는 큰 그림이고, 각 서비스를 본인 것으로 만들고 다루는 법은 이어지는 상세 가이드 3개에 있습니다.

이 문서는 **개발을 전혀 몰라도** 읽고 따라 할 수 있게 쓰였습니다. 어려운 말이 나오면 바로 옆 괄호에 쉬운 풀이를 붙였습니다.

---

## 1. 바이브 코딩이 대체 뭔가요?

**바이브 코딩(vibe coding)** = 사람이 코드를 한 줄씩 타이핑하지 않고, AI에게 **"이런 걸 이렇게 만들어줘 / 이건 이렇게 고쳐줘"라고 평소 말로 지시**하면 AI가 대신 코드를 짜고 고쳐주는 개발 방식입니다. (2025년 이후 크게 퍼진 방식으로, 개발자가 아니어도 직접 만들 수 있게 된 것이 핵심입니다.)

비유하면 이렇습니다.

| | 예전 방식 (전통 코딩) | 바이브 코딩 |
|---|---|---|
| 집 짓기에 비유하면 | 벽돌을 직접 하나하나 쌓음 | **"큰 창문 있는 거실 하나 만들어줘"** 라고 말하면 AI 목수가 알아서 지음 |
| 사람이 하는 일 | "어떻게(코드 문법)" 까지 전부 | **"무엇을 · 왜"** 에 집중 (아이디어·판단·검수) |
| 개발 지식 | 필수 | 없어도 시작 가능 (AI가 담당) |

즉 **좋은 아이디어와 "이게 맞나?"를 판단하는 눈만 있으면**, 코드는 AI가 만들어 줍니다. 이 가이드의 목표는 여러분이 그 판을 직접 깔 수 있게 하는 것입니다.

> 💡 **실제 사례로 증명됨**: 사내에서 실제 운영 중인 "카카오 상담 수집" 서비스도 개발자가 코드를 한 줄씩 짠 게 아니라, 이 바이브 코딩 방식으로 만들어져 지금도 매일 자동으로 돌고 있습니다. 여러분도 각자 본인 아이디어로 이렇게 만들 수 있습니다.

---

## 2. 왜 이 세 서비스가 필요한가요?

"AI가 다 만들어준다면서 왜 GitHub·Supabase·Vercel을 배워야 하죠?" 라는 의문이 자연스럽습니다. 답은 이렇습니다.

AI가 코드를 **만들어주긴** 하지만, 그 결과물은 어딘가에 **보관하고 · 데이터를 저장하고 · 실제로 공개**해야 진짜 서비스가 됩니다. 그 세 가지를 담당하는 곳이 이 셋입니다.

| 서비스 | 비유 | 하는 일 | 무료 시작 |
|---|---|---|---|
| **GitHub** (깃허브) | 설계도 보관소 + 공사 일지 | AI가 만든 코드를 보관하고 변경 이력을 기록 | ✅ 무료 |
| **Supabase** (슈파베이스) | 창고 + 관리사무소 + 자동화 직원 | 데이터 저장, 로그인 관리, 정해진 시각 자동 실행 | ✅ 무료 플랜 |
| **Vercel** (베르셀) | 자동 시공사 | 코드가 바뀌면 자동으로 웹사이트를 지어 공개 | ✅ 무료 플랜 |

세 곳 다 **개인이 무료로 시작**할 수 있습니다. 이 셋을 이해하면 AI에게 훨씬 정확히 지시할 수 있습니다. (예: "이 데이터는 Supabase에 저장하게 해줘", "이 변경은 Vercel 미리보기로 먼저 띄워줘")

> ℹ️ 참고: 만드는 아이디어에 따라 세 개가 다 필요하진 않습니다. **간단한 웹사이트**면 GitHub + Vercel만, **데이터·자동화가 필요한 서비스**(예: 상담 수집 같은)면 Supabase까지 씁니다.

---

## 3. 이 세 개가 어떻게 맞물려 돌아가나 (기본 흐름)

여러분이 AI에게 지시해 뭔가 만들면, 아래 순서로 이어집니다.

```
① AI에게 "이런 거 만들어줘 / 이렇게 고쳐줘" 지시
        ▼
② 결과 코드가 GitHub 에 올라감 (백업 + 변경 기록)
        ▼
③ Vercel 이 감지해 웹사이트를 자동으로 지어 인터넷에 공개 (배포)
        ▼
④ 사이트가 필요할 때 Supabase 에서 데이터·로그인 정보를 가져다 씀
```

한 줄 요약: **코드가 GitHub에 올라가면 → Vercel이 자동으로 사이트를 띄우고 → 그 사이트는 Supabase 창고에서 데이터를 꺼내 쓴다.**

> 데이터·자동화만 있고 화면이 없는 서비스(예: 카카오 상담 수집)는 ③ Vercel 없이 **Supabase 안에서만** 자동으로 돌기도 합니다.

---

## 4. 이 가이드로 배우게 되는 것

역할을 "보기만"으로 한정하지 않습니다. **본인 것을 직접 만들고 다루는 법**을 배웁니다.

| 서비스 | 배우는 것 |
|---|---|
| **② GitHub** | 본인 계정·저장소 만들기, AI 도구 연결, 변경 검토·합치기, 되돌리기 |
| **③ Supabase** | 본인 프로젝트 만들기, 데이터 표 만들고 조회, 자동작업 이해·운영 |
| **④ Vercel** | 본인 사이트 배포, 미리보기 확인, 정식 반영, 문제 시 롤백 |

---

## 5. 추천 시작 순서 (처음이라면 이 순서로)

1. **GitHub 계정 + 첫 저장소 만들기** (→ ② 가이드)
2. **바이브 코딩 도구 준비** (예: Claude Code, Cursor 등 AI 코딩 도구를 본인 저장소에 연결)
3. **작은 아이디어 하나를 AI에게 지시**해 만들어 보기 (예: "메모를 저장하는 간단한 웹페이지 만들어줘")
4. **Vercel 연결해 인터넷에 공개**해 보기 (→ ④ 가이드)
5. 데이터·로그인·자동화가 필요해지면 **Supabase 붙이기** (→ ③ 가이드)

> 처음엔 "완벽한 서비스"를 목표로 하지 말고, **아주 작은 것 하나를 끝까지(만들기 → 공개까지) 해보는 것**이 가장 빠른 학습입니다.

---

## 6. 공통 안전 수칙 (되돌리기 어려운 것만 조심)

본인 연습 프로젝트이니 마음껏 시도하되, 아래만 조심하면 됩니다.

1. **삭제(Delete)·"영구"·빨간 버튼은 실행 전 한 번 더 확인.** 프로젝트·저장소·데이터 삭제는 되돌리기 어렵습니다.
2. **비밀값(키·토큰·비밀번호)은 화면에 보여도 외부로 내보내지 않기.** 특히 **코드에 키를 그대로 적어 GitHub에 올리지 않기** (AI에게 "환경변수로 빼줘"라고 시키면 됩니다).
3. **큰 변경은 "미리보기 / 사본"에서 먼저** 확인한 뒤 정식 반영.
4. **확신이 안 서면 AI에게 먼저 물어보기.** "이거 눌러도 돼? 되돌릴 수 있어?" 라고 확인시키고 진행하면 안전합니다.

- **② GitHub** (본인 저장소 만들기 · AI 연결 · 검토·합치기)
