# 바이브 코딩 실전 가이드 ④ Vercel

> **바이브 코딩 실전 가이드 시리즈**: ① 시작하기 · ② GitHub · ③ Supabase · **④ Vercel (이 문서)**

> 📌 **한 줄 요약**
> Vercel(베르셀)은 **웹사이트를 세상에 자동으로 띄워주는 "자동 시공사"** 입니다.
> 코드가 GitHub에 올라가면, Vercel이 알아서 사이트를 새로 지어 인터넷에 공개합니다 (sdij-wiki.vercel.app).
> 기획자는 주로 **"배포가 잘 됐는지(초록불)"** 와 **"바뀐 걸 미리보기로 먼저 확인"** 하게 됩니다.

---

## 1. Vercel이 뭔가요? (비유)

예전엔 웹사이트를 인터넷에 올리려면 서버를 빌리고, 설정하고, 파일을 복사하고... 개발자가 손으로 여러 단계를 해야 했습니다. Vercel은 그걸 **전자동**으로 만든 서비스입니다.

- GitHub에 코드가 올라오는 순간 **자동 감지**
- 그 코드로 **웹사이트를 새로 지음** (이 과정을 "빌드 → 배포"라고 함)
- 완성되면 **인터넷 주소로 바로 공개** (신축 건물에 자동 입주)

우리 사이트는 **`sdij-wiki`** 프로젝트로 관리되고, 팀 이름은 **`layr8xs-projects`**, 운영 주소는 **https://sdij-wiki.vercel.app** 입니다.

---

## 2. 접속 준비 (처음 한 번만)

### 1단계. 계정 만들기
**https://vercel.com/login 에서 GitHub 계정으로 로그인**하는 게 가장 간단합니다.

### 2단계. 팀(Team)에 초대받기
우리 사이트는 `layr8xs-projects` 라는 팀 안에 있어, 초대돼야 보입니다.
- **관리자(사장님)에게 "제 Vercel 로그인 이메일은 OOO 입니다. 팀에 초대해 주세요" 요청**하세요.
- 초대 메일의 **`Accept`** 를 누르면 됩니다.

> 관리자 참고: Vercel → 팀 → Settings → Members → Invite. 기획자에겐 **`Viewer`(뷰어, 보기 전용)** 또는 **`Member`** 권한이면 충분합니다.

### 접속 확인
로그인 후 프로젝트 목록에서 **`sdij-wiki`** 를 클릭해 들어가지면 성공입니다.

## 3. 화면 둘러보기 (상단 탭 지도)

프로젝트에 들어가면 위쪽에 탭이 있습니다. 기획자 기준으로 정리합니다.

| 탭 | 우리말 | 여기서 뭘 하나 |
|---|---|---|
| **Project (첫 화면)** | 개요 | 지금 어떤 버전이 떠 있는지, 최근 배포 상태 한눈에 |
| **Deployments** | 배포 이력 | **언제 무엇을 배포했고 성공했는지** 목록 (기획자 주 무대) |
| **Analytics** | 방문 통계 | 방문자 수·인기 페이지 등 (켜져 있을 때) |
| **Domains** | 도메인(주소) | 사이트 인터넷 주소 목록 |
| **Logs** | 기록 | 오류·접속 기록 (개발자용) |
| **Settings** | 설정 | ⚠️ 기획자는 들어가지 않습니다 |

> 📷 (컨플루언스에 Deployments 목록 화면 캡처를 넣으면 좋습니다: 상태 아이콘이 잘 보이게)

---

## 4. 기획자 실전: 이런 걸 하게 됩니다

### 실전 A. "방금 바꾼 게 사이트에 잘 올라갔나?" 확인
가장 자주 하는 일입니다.

1. **`Deployments` 탭** 클릭
2. 맨 위가 가장 최근 배포입니다. **상태 아이콘**을 봅니다:

| 표시 | 뜻 | 판단 |
|---|---|---|
| 🟢 **Ready** | 성공, 지금 사이트에 반영됨 | 정상 |
| 🟡 **Building** | 짓는 중 (보통 1~2분) | 잠시 기다리기 |
| 🔴 **Error / Failed** | 실패 | 개발자에게 알림 (단, 사이트는 직전 정상본이 계속 떠 있어 안 꺼짐) |
| ⚪ **Canceled** | 취소됨 | **실패 아님.** 더 최신 배포가 들어와 이전 것을 자동으로 멈춘 것 |

> 💡 안심 포인트: 새 배포가 실패해도 Vercel은 **직전 정상 버전을 계속 띄워둬서** 사이트가 꺼지지 않습니다.

### 실전 B. 정식 공개 전에 "미리보기"로 먼저 확인
바이브 코딩에서 아주 유용합니다. 아직 정식 반영 전인 변경을 **미리보기 링크**로 먼저 볼 수 있습니다.

1. `Deployments` 목록에서 **`Preview`(미리보기)** 표시가 붙은 항목 클릭
2. **`Visit` 또는 미리보기 주소** 클릭 → 바뀐 사이트를 실제로 열어 확인
3. 좋으면 개발자에게 "반영해도 좋아요", 아니면 "여기 이렇게 고쳐주세요" 라고 이슈/PR에 남기기

> 미리보기 주소는 `sdij-wiki-git-...vercel.app` 처럼 길게 생겼습니다. 정식 주소(`sdij-wiki.vercel.app`)와 다릅니다.

### 실전 C. 사이트 주소(도메인) 확인
1. **`Domains` 탭** 또는 개요 화면
2. 정식 주소가 **`sdij-wiki.vercel.app`** 임을 확인할 수 있습니다.

### 실전 D. 방문 통계 보기 (켜져 있을 때)
1. **`Analytics` 탭** → 방문자 수, 많이 본 페이지 등 확인

## 5. 절대 하지 말 것 (안전선)

| 하지 말 것 | 이유 |
|---|---|
| **`Settings` 안의 값 변경** | 빌드 설정·연동을 건드리면 사이트가 안 지어질 수 있습니다 |
| **`Environment Variables`(환경변수, 비밀값) 열람·복사·전송** | Supabase 키 등 비밀이 들어 있습니다. 밖으로 내보내면 유출 |
| **`Rollback`(되돌리기) · `Redeploy`(재배포) 함부로 클릭** | 사이트가 옛 버전으로 갑자기 바뀔 수 있습니다. 개발자와 상의 후에만 |
| **`Domains`에서 주소 삭제 / `Delete Project`** | 사이트가 인터넷에서 사라집니다 |

기획자는 **"배포 상태 보기 · 미리보기 열기 · 통계 보기"** 까지만 하면 안전합니다.

---

## 6. 용어 사전 (자주 나오는 말)

| 용어 | 쉬운 뜻 |
|---|---|
| 배포 (Deploy) | 코드를 실제 웹사이트로 만들어 인터넷에 올리는 것 |
| 빌드 (Build) | 코드를 사이트 형태로 "짓는" 과정 (배포의 앞 단계) |
| 프로덕션 (Production) | 실제 사용자가 보는 정식 사이트 (운영) |
| 프리뷰 (Preview) | 정식 반영 전, 미리 확인용으로 따로 띄운 사이트 |
| 도메인 (Domain) | 사이트 인터넷 주소 (우리: sdij-wiki.vercel.app) |
| 롤백 (Rollback) | 문제가 생겼을 때 이전 정상 버전으로 되돌리기 |
| 환경변수 (Env Variable) | 코드에 직접 안 쓰고 몰래 보관하는 비밀 설정값 (키 등) |

## 7. (참고) 개발자·AI는 실제로 어떻게 연결하나

기획자는 결과만 확인하면 되지만, 원리를 짧게 적습니다. (안 읽으셔도 됩니다.)

1. Vercel은 우리 **GitHub 저장소와 연결**돼 있습니다.
2. 그래서 GitHub의 `main`에 코드가 올라가면(= 머지되면) **자동으로 정식 배포(프로덕션)** 가 시작됩니다.
3. 아직 검토 중인 변경(PR)에는 **자동으로 미리보기(프리뷰)** 를 만들어 줍니다. 그래서 정식 반영 전에 확인이 가능합니다.
4. 사이트가 Supabase 창고에 접속할 때 쓰는 **키는 Vercel의 환경변수**에 비밀로 저장돼 있습니다.

즉 "GitHub에 올림 → Vercel 자동 배포 → Supabase 데이터 사용"이 한 줄로 이어지는 것입니다. (①번 시작하기 문서의 흐름도 참고)

## 8. 문제가 생기면

| 증상 | 이렇게 하세요 |
|---|---|
| 로그인은 됐는데 `sdij-wiki`가 안 보임 | 팀 초대 미수락 가능성. 관리자에게 재초대 요청 |
| 최근 배포가 🔴 실패로 뜸 | 사이트 자체는 직전 버전이 살아 있으니 당황 금지. 화면 캡처해 개발자에게 전달 |
| 사이트가 옛날 모습으로 보임 | 브라우저 새로고침(Ctrl/Cmd + Shift + R). 그래도면 개발자 문의 |
| 미리보기 주소가 안 열림 | 미리보기는 임시라 시간이 지나면 만료될 수 있음. 최신 것으로 다시 확인 |

> 확신이 안 서면 **보기만 하고**, 되돌리기·재배포 같은 버튼은 개발자와 상의 후 누르세요.
