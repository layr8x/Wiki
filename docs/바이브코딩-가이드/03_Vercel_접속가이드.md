# 바이브 코딩 실전 가이드 ④ Vercel

> **바이브 코딩 실전 가이드 시리즈**: ① 시작하기 · ② GitHub · ③ Supabase · **④ Vercel (이 문서)**

> 📌 **한 줄 요약**
> Vercel(베르셀)은 **웹사이트를 세상에 자동으로 띄워주는 "자동 시공사"** 입니다.
> 본인 GitHub 저장소를 한 번 연결해 두면, 코드가 바뀔 때마다 **자동으로 사이트를 새로 지어 인터넷에 공개**합니다.
> 여러분은 **배포 확인 → 미리보기 → 정식 반영 → 문제 시 되돌리기(롤백)** 를 직접 하게 됩니다.

> ℹ️ **언제 쓰나**: 만든 결과가 **화면(웹사이트)** 일 때 씁니다. 데이터·자동화만 있고 화면이 없는 서비스(예: 상담 수집 같은)는 Vercel 없이 Supabase만으로도 됩니다.

---

## 1. Vercel이 뭔가요? (비유)

예전엔 웹사이트를 인터넷에 올리려면 서버를 빌리고, 설정하고, 파일을 복사하고... 여러 단계를 손으로 했습니다. Vercel은 그걸 **전자동**으로 만든 서비스입니다.

- GitHub에 코드가 올라오는 순간 **자동 감지**
- 그 코드로 **웹사이트를 새로 지음** ("빌드 → 배포")
- 완성되면 **인터넷 주소로 바로 공개** (신축 건물 자동 입주)

개인은 **무료 플랜**으로 본인 사이트를 띄울 수 있습니다.

---

## 2. 본인 것 만들기 (처음 한 번만)

### 1단계. 가입
**https://vercel.com/signup 에서 GitHub 계정으로 로그인**이 가장 간단합니다.

### 2단계. 내 저장소 연결해서 첫 배포
1. **`Add New...` → `Project`** 클릭
2. 목록에서 **본인 GitHub 저장소**(②에서 만든 것)를 선택 → **`Import`**
   - 처음이면 "Vercel이 내 GitHub에 접근하도록 허용" 한 번 승인해야 목록에 뜹니다.
3. 설정은 대부분 자동 감지됩니다. 그대로 **`Deploy`** 클릭
4. 1~2분 뒤 사이트 주소가 나옵니다 (예: `내프로젝트.vercel.app`)

이제 GitHub에 코드가 올라갈 때마다 **자동으로 다시 배포**됩니다. 한 번만 연결하면 끝입니다.

## 3. 화면 둘러보기 (상단 탭 지도)

| 탭 | 우리말 | 여기서 뭘 하나 |
|---|---|---|
| **Project (첫 화면)** | 개요 | 지금 어떤 버전이 떠 있는지, 최근 배포 상태 |
| **Deployments** | 배포 이력 | **언제 무엇을 배포했고 성공했는지** 목록 + 되돌리기 |
| **Analytics** | 방문 통계 | 방문자 수·인기 페이지 (켜면) |
| **Domains** | 도메인(주소) | 사이트 주소 관리 (원하면 나만의 주소 연결) |
| **Settings** | 설정 | 환경변수(비밀값)·빌드 설정. 신중히 |

> 📷 (컨플루언스에 Deployments 목록 캡처를 넣으면 좋습니다: 상태 아이콘이 잘 보이게)

## 4. 실전: 직접 해보기

### 실전 A. "방금 바꾼 게 사이트에 올라갔나?" 확인
1. **`Deployments` 탭** → 맨 위가 가장 최근 배포
2. **상태 아이콘**을 봅니다:

| 표시 | 뜻 | 판단 |
|---|---|---|
| 🟢 **Ready** | 성공, 지금 사이트에 반영됨 | 정상 |
| 🟡 **Building** | 짓는 중 (보통 1~2분) | 잠시 대기 |
| 🔴 **Error / Failed** | 실패 | AI에게 원인 확인 (단, 직전 정상본이 계속 떠 있어 사이트는 안 꺼짐) |
| ⚪ **Canceled** | 취소됨 | **실패 아님.** 더 최신 배포가 들어와 이전 것을 자동으로 멈춘 것 |

> 💡 안심 포인트: 새 배포가 실패해도 Vercel은 **직전 정상 버전을 계속 띄워둬서** 사이트가 꺼지지 않습니다.

### 실전 B. 정식 공개 전에 "미리보기"로 먼저 확인
AI가 뭔가 바꿨을 때, 정식 반영 전에 **미리보기 링크**로 먼저 봅니다.
1. `Deployments`에서 **`Preview`(미리보기)** 표시 항목 클릭
2. **`Visit` 또는 미리보기 주소** 클릭 → 바뀐 사이트를 실제로 열어 확인
3. 좋으면 GitHub에서 그 PR을 **머지** → 정식 반영. 아니면 "여기 고쳐줘"라고 AI에게 다시 요청

### 실전 C. 정식 반영은 어떻게 되나
- GitHub에서 PR을 **`main`에 머지**하면, Vercel이 자동으로 **정식(Production) 배포**를 시작합니다. 별도 버튼 불필요.

### 실전 D. 문제 생기면 이전 버전으로 되돌리기 (롤백)
정식 반영 후 문제가 보이면, 지난 정상 버전으로 즉시 되돌릴 수 있습니다.
1. `Deployments`에서 🟢 **Ready 였던 이전 정상 배포** 찾기
2. 오른쪽 **`···` → `Promote to Production`(또는 Rollback)** → 그 버전이 다시 정식으로

> ⚠️ 롤백은 사이트를 옛 모습으로 바꾸는 실제 작업이라, 누르기 전 "어느 버전으로 가는지" 확인하세요. 헷갈리면 AI에게 "지금 롤백하면 어느 시점으로 돌아가?" 물어보고 진행.

---

## 5. 되돌리기 어려운 것 (주의)

| 주의 대상 | 왜 |
|---|---|
| **`Settings → Environment Variables`(비밀값) 열람·복사·전송** | Supabase 키 등 비밀이 있음. 밖으로 내보내면 유출 |
| **`Settings`의 빌드 설정 변경** | 잘못 바꾸면 사이트가 안 지어짐. 바꾸기 전 AI에게 확인 |
| **`Domains`에서 주소 삭제 / `Delete Project`** | 사이트/프로젝트가 사라짐 |

> 배포 확인·미리보기·통계 보기는 아무리 해도 안전합니다. 롤백은 "실제로 사이트를 바꾸는" 작업이니 대상만 확인하고 하세요.

## 6. 용어 사전

| 용어 | 쉬운 뜻 |
|---|---|
| 배포 (Deploy) | 코드를 실제 웹사이트로 만들어 인터넷에 올리는 것 |
| 빌드 (Build) | 코드를 사이트 형태로 "짓는" 과정 (배포의 앞 단계) |
| 프로덕션 (Production) | 실제 방문자가 보는 정식 사이트 |
| 프리뷰 (Preview) | 정식 반영 전, 미리 확인용으로 따로 띄운 사이트 |
| 롤백 (Rollback) / Promote | 이전 정상 버전을 다시 정식으로 올리는 것 |
| 도메인 (Domain) | 사이트 인터넷 주소 |
| 환경변수 (Env Variable) | 코드에 직접 안 쓰고 몰래 보관하는 비밀 설정값 (키 등) |

---

## 7. 연결 원리 (AI와 함께 실제로 어떻게 도나)

1. Vercel은 여러분의 **GitHub 저장소와 연결**돼 있습니다.
2. GitHub `main`에 코드가 머지되면 **자동으로 정식 배포** 시작.
3. 검토 중인 변경(PR)에는 **자동으로 미리보기(프리뷰)** 를 만들어 줌 (정식 전 확인 가능).
4. 사이트가 Supabase에 접속하는 **키는 Vercel 환경변수에 비밀로** 저장합니다 (AI가 처리해 줌).

즉 "GitHub 머지 → Vercel 자동 배포 → (필요 시) Supabase 데이터 사용" 이 한 줄로 이어집니다. (①번 시작하기의 흐름도 참고)

---

## 8. 문제가 생기면

| 증상 | 이렇게 하세요 |
|---|---|
| Import 목록에 내 저장소가 없음 | Vercel의 GitHub 접근 권한 승인 필요. `Add New → Project`에서 권한 조정 |
| 최근 배포가 🔴 실패 | 사이트는 직전 버전이 살아 있으니 당황 금지. 오류 화면 캡처해 AI에게 원인 요청 |
| 사이트가 옛날 모습 | 브라우저 강력 새로고침(Ctrl/Cmd + Shift + R) |
| 정식 반영 후 문제 발견 | 실전 D의 **롤백**으로 이전 정상 버전 복구 |
