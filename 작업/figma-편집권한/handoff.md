# 인계장

검사역 두 곳이 어디를 봐야 하는지 적는다.

## 넘기는 것

`요청.md` 한 장. 받는 사람은 각 Figma 파일 소유자다.

## 검사역이 볼 곳

| 무엇 | 어디 | 어떻게 확인 |
|---|---|---|
| 숫자 재현 | `요청.md` 의 26, 18, 0, 14 | `근거.md` 각 줄의 출처를 그대로 다시 실행 |
| 인과 표현 | "원인이 특정됩니다" 문장 | 대조가 실제로 있는지. 계정 조회 성공과 파일 조회 실패 |
| 못 잰 것 표기 | 노드 유효성 문단 | 추정으로 채우지 않았는지 |
| 결정 요청 | 첫 줄 | 요청이 하나인지. 둘이면 기획으로 되돌린다 |

## 말 검사역이 볼 곳

받는 사람이 개발자가 아닐 수 있다. 용어를 풀었는지 본다.
연결 도구, 노드, 플랜, 좌석. 이 넷이 풀이 없이 쓰였으면 걸린다.

## 이미 되돌린 것 하나

처음에 참조 파일 수를 19개로 적었다. 파일별로 세어 중복을 두 번 셌다.
중복 제거하면 14개다. 검산에서 걸려 고쳤다.

## 되돌린 것 둘

참조 파일 수를 다시 재니 15개가 나왔다. 이 작업 폴더가 그 식별자를 담고 있어 스스로를 센 것이다.
작업 폴더를 빼면 14개다. 출처 칸에 측정 범위를 적었다.
