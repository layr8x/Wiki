# desk

한 사람이 조직처럼 일하기 위한 스킬(= 상황에 맞게 자동으로 펼쳐지는 지침서) 묶음.
부서 9개로 나뉘고, 각 부서는 따로 설치한다.

## 구조

```
의도 고정(brief)
  필요한 분야만 병행: 콘텐츠 · 기획 · 디자인 · 분석 · 개발
    하나로 묶기(weave)
      검사역 둘 통과
        발행
```

| 단 | 부서 | 하는 일 |
|---|---|---|
| 묶는 층 | `chief` 편집장 | 착수 전 의도 고정, 분야 간 접합, 의사결정 방법론 |
| 다섯 분야 | `persuade` 콘텐츠 | 보고서·기획서·공지의 뼈대와 문체 |
| | `product` 기획 | 무엇을 만들지, 우선순위, 범위 |
| | `screens` 디자인 | 디자인시스템, 화면 설계, 접근성 |
| | `numbers` 분석 | 지표 정의, 인과 추론, 근거 만들기 |
| | `build` 개발 | 구현 판단과 품질 기준 |
| 검사역 | `plain` 말 검사역 | 안 풀어쓴 용어와 번역투를 막는다 |
| | `verify` 검사역 | 완료 보고 전 실제 검증 |
| 교체 | `site` 현장 | 지금 일하는 곳의 고유 값. 저장소(= 코드와 이력을 모아둔 곳), 도구, 사람 |

검사역 둘은 막을 권한이 있다. 통과하지 못한 산출물은 나가지 않는다.

## 어디서든 돈다

`site`를 뺀 여덟 부서에는 회사명, 제품명, 파일 식별자가 들어가지 않는다.
회사를 옮기면 틀리게 되는 것은 전부 `site`에 있다.

말 검사역은 측정기와 용어사전을 부서 안에 들고 다닌다. 설치만 하면 경로를 고칠 일이 없고,
Stop 시점에 자동으로 돌아 위험이 있으면 작업을 막는다.

## 설치

```
/plugin marketplace add <저장소>
/plugin install chief@desk
/plugin install plain@desk
```

전부 깔 필요는 없다. 필요한 부서만 설치한다.

## 새 직장으로 옮길 때

1. `site` 부서의 스킬을 비우고 새 직장 정보로 채운다
2. `.claude-plugin/desk.local.json`을 새로 쓴다. 설치 주소와 저장소별 예외
3. 다른 부서에 옛 직장 이름이 남아 있으면 `site`로 옮긴다
4. `python3 scripts/build-org-chart.py`로 조직도를 다시 만든다

## 방법론

다섯 분야와 편집장에 각각 `*-methods` 스킬이 있다. 그 분야에서 검증된 방법론을
언제 쓰는지와 함께 정리해 뒀다. 방법론 이름은 항상 한 줄 풀이를 붙여 쓴다.
