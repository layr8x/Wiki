# 현장 자료

다른 부서는 어디서든 그대로 돌아간다. **현장에서만 통하는 것은 전부 이 부서에 모은다.**
직장이 바뀌면 이 부서를 새로 쓰고 나머지는 손대지 않는다.

## 담는 것

| 칸 | 예 |
|---|---|
| 제품 | 이름, 사용자, 지금 단계 |
| 저장소(= 코드와 변경 이력을 모아둔 곳)와 배포(= 실제로 사이트에 올리는 일) | 어디에 코드가 있고 어디로 나가는가 |
| 데이터 출처 | 어떤 보관함에 무엇이 있고 누가 여는가 |
| 도구 | 디자인 도구 파일 위치, 이슈 관리, 메신저 |
| 디자인시스템 | 이름, 토큰(= 값에 붙인 이름) 규칙, 컴포넌트 |
| 사람 | 결정권자, 유관부서, 협업 창구 |
| 그곳의 규칙 | 표기법, 승인 절차, 금지 사항 |

## 담지 않는 것

방법론과 판단 기준은 여기가 아니다. 그건 각 부서에 있고 어디서든 같다.
**여기에 들어갈 기준은 하나다. 회사를 옮기면 틀리게 되는가.** 그러면 현장 자료다.

## 새 직장으로 옮길 때

1. 이 부서의 스킬(= 상황에 맞게 펼쳐지는 지침서) 을 전부 비운다
2. 위 일곱 칸을 새로 채운다
3. 다른 부서에서 옛 직장 이름이 나오면 그건 잘못 들어간 것이다. 이리로 옮긴다

## 하지 말 것

- 다른 부서 스킬 본문에 회사명, 제품명, 파일 식별자를 적기
- 여기에 일반 원칙을 적기. 그건 옮겨도 유효하니 부서 쪽이다
- 자격 증명이나 개인정보를 적기. 그건 어느 쪽에도 적지 않는다
