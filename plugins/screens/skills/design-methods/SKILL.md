# 디자인 방법론

## 고르는 법

| 상황 | 쓸 것 |
|---|---|
| 화면이 어렵다는 말을 들음 | 휴리스틱 평가, 인지 부하 |
| 왜 이렇게 배치했는지 설명 | 게슈탈트 원리 |
| 버튼 크기와 위치 판단 | 피츠 법칙 |
| 선택지가 너무 많음 | 힉 법칙 |
| 간격과 크기 규칙 정하기 | 8배수 격자, 모듈러 스케일 |
| 색과 글자가 안 보임 | 명도 대비 기준 |
| 컴포넌트를 어떻게 나눌지 | 원자 디자인, 디자인 토큰(= 색·간격 같은 값에 붙인 이름) |
| 사용자가 왜 실패하는지 | 행동 7단계 |

## 방법론

**휴리스틱 평가 10원칙**(야콥 닐슨)
시스템 상태 가시성, 현실 세계와의 일치, 사용자 통제와 자유, 일관성, 오류 예방, 기억보다 인식,
유연성, 미학적 절제, 오류 인식과 복구, 도움말. 열 가지로 화면을 훑는다.
사용자 조사 없이 빠르게 문제를 찾는 용도다. **조사를 대신하지는 않는다.**

**게슈탈트 원리**
가까운 것끼리 한 덩어리로, 닮은 것끼리 한 무리로, 닫힌 형태를 하나로 본다.
간격이 위계를 만든다는 말의 근거가 이것이다. **선을 긋기 전에 간격으로 묶어 본다.**

**피츠 법칙**
목표가 크고 가까울수록 빨리 누른다. 화면 가장자리는 무한히 큰 표적처럼 동작한다.
자주 쓰는 버튼은 크고 가깝게, 위험한 버튼은 작고 멀게.

**힉 법칙**
선택지가 늘면 고르는 시간이 늘어난다. 다만 선택지가 잘 묶여 있으면 덜 늘어난다.
메뉴를 줄이는 것만이 답은 아니고, **묶어서 계층을 만드는 것도 답이다.**

**인지 부하 이론**(존 스웰러)
사람이 한 번에 다룰 수 있는 작업 기억은 좁다. 화면이 어렵다는 말은 대개 여기서 온다.
과제와 무관한 부하를 먼저 걷어낸다. 장식, 중복 설명, 불필요한 선택지.

**행동 7단계**(도널드 노먼)
목표, 계획, 구체화, 실행, 지각, 해석, 비교. 사용자가 어디서 막히는지 단계로 짚는다.
"실행의 간극"은 뭘 해야 할지 몰라서, "평가의 간극"은 됐는지 몰라서 생긴다.

**8배수 격자와 모듈러 스케일**
간격을 8의 배수로, 글자 크기를 일정 비율로 늘린다.
숫자 자체가 옳아서가 아니라 **결정을 줄이고 화면 사이 일관성을 만들어서** 쓴다.

**명도 대비 기준**(WCAG)
본문 글자는 배경과 4.5대 1, 큰 글자는 3대 1 이상. 접근성 국제 표준의 수치다.
연한 회색 본문은 이 기준에서 대부분 떨어진다. 눈으로 판정하지 말고 계산한다.

**원자 디자인**(브래드 프로스트)
원자, 분자, 유기체, 템플릿, 페이지. 작은 것부터 조립한다.
계층 이름 자체보다 **어디까지가 재사용 단위인지 합의하는 것**이 실제 값이다.

**디자인 토큰**
색과 간격, 글자 크기에 이름을 붙여 값 대신 이름을 쓴다.
값을 직접 쓰면 바꿀 때 전부 찾아야 하고, 이름을 쓰면 한 곳만 고친다.

## 검증

눈대중으로 판정하지 않는다. 원본과 화면을 같은 배율로 놓고 수치를 대조한다.
간격, 글자 크기, 색값, 대비를 숫자로 비교하고 다르면 어디가 다른지 적는다.

## 하지 말 것

- 원칙 이름으로 결정을 정당화하기. 무엇이 나아지는지가 근거다
- 대비를 눈으로 판정하기
- 컴포넌트를 만들기 전에 계층 이름부터 정하기
- 검증 전에 완료라고 하기
