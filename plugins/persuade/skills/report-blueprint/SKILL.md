# 보고서 뼈대

이 문서의 목적은 정보 전달이 아니다. **결정을 받아내는 것**이다.
읽는 사람이 무엇을 승인해야 하는지 첫 세 줄 안에 모르면 실패한 문서다.

## 순서 (피라미드 원칙 = 결론을 맨 위에 두고 근거를 아래에 까는 방식)

1. **결정 요청** 한두 줄. "무엇을 승인해달라" 또는 "무엇을 결정해달라"
2. **근거** 세 개 이하. 각 근거마다 숫자 하나와 그 출처
3. **예상 반론**과 답 (objection-first 참고)
4. **안 하면 생기는 일**. 현상 유지의 비용
5. 부록. 방법, 원자료, 상세 표

1번이 없으면 나머지를 쓰지 않는다. 결정 요청을 못 쓰겠다면 아직 문서를 쓸 때가 아니다.

## 청중별로 자른다

한 벌을 쓰고 잘라낸다. 세 벌을 따로 쓰지 않는다.

| 읽는 사람 | 분량 | 남길 것 | 뺄 것 |
|---|---|---|---|
| 경영진 | 1장 | 결정 요청, 숫자 3개, 비용 | 방법, 과정, 화면 |
| 유관부서 | 3장 내외 | 결정 요청, 근거 전체, 반론 | 원자료 |
| 개발팀 | 규격표 | 화면 규격, 데이터 정의, 예외 처리 | 배경 설명 |

## 반드시 지킬 것

- 결론을 맨 위에. 배경부터 시작하는 문서는 끝까지 안 읽힌다
- 숫자마다 잰 것인지 추정인지 표시 (number-tags 참고)
- 문단 분량을 일부러 불균형하게. 중요한 건 길게, 사소한 건 한 줄
- 줄표(길게 늘인 대시), 세미콜론, 절 기호를 쓰지 않는다
- 문장을 접속부사로 시작하지 않는다
- "첫째, 둘째" 병렬을 쓰지 않는다

## 넘기기 전 확인

문서를 넘길 때 **질문받을 만한 곳 세 군데**를 같이 적어 준다.
김명준님이 회의에서 직접 설명하지 못하는 문서는 완성이 아니다.

## 하지 말 것

- 결정 요청 없이 "공유드립니다"로 끝내기
- 근거를 다섯 개 이상 나열하기. 세 개를 넘으면 초점이 흐려진다
- 반론을 부록에 숨기기
