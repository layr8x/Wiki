# 의사결정 방법론

방법론은 많이 아는 게 아니라 **맞는 것을 고르는 게** 실력이다. 상황부터 판정한다.

## 고르는 법

| 상황 | 쓸 것 |
|---|---|
| 문제가 크고 어디부터인지 모름 | 이슈 트리, MECE |
| 원인 후보가 여럿 | 가설 주도 문제해결 |
| 되돌리기 어려운 선택 | 유형 1과 2 구분, 사전부검 |
| 상황 자체가 불확실 | 커네빈 |
| 나중에 왜 그랬는지 물을 것 | 의사결정 기록 |
| 목표에서 거꾸로 짜야 함 | 역산 기획 |

## 방법론

**MECE**(= Mutually Exclusive, Collectively Exhaustive, 겹치지 않고 빠짐없이)
문제를 쪼갤 때 조각이 서로 안 겹치고 다 합치면 전체가 되게 나눈다.
겹치면 같은 걸 두 번 세고, 빠지면 원인을 놓친다. 맥킨지에서 정착한 방식.

**이슈 트리**
큰 질문 하나를 하위 질문으로 가지치기해 잎에서 검증 가능한 것까지 내려간다.
잎이 "재 볼 수 있는 것"이 아니면 더 쪼갠다.

**가설 주도 문제해결**
답을 먼저 세우고 그것을 깨는 데이터를 찾는다. 자료를 다 모으고 결론을 내는 것보다 빠르다.
주의할 점은 확증 편향이다. **깨는 증거를 먼저 찾는다**고 정해두면 덜 걸린다.

**유형 1과 2 의사결정**(아마존)
되돌릴 수 없는 결정은 느리게, 되돌릴 수 있는 결정은 빠르게.
대부분의 결정은 유형 2인데 유형 1처럼 다뤄져 시간을 먹는다.

**사전부검**(pre-mortem, 게리 클라인)
실행 전에 "이 일이 6개월 뒤 실패했다고 치자. 왜 실패했나"를 먼저 적는다.
사후 분석보다 값이 싸고, 반대 의견을 꺼내기 쉬운 형식이라 잘 나온다.

**커네빈**(Cynefin, 데이브 스노든)
상황을 넷으로 나눈다. 명확(정답 있음), 난해(전문가 필요), 복잡(해 보고 배움), 혼돈(일단 멈춤).
복잡한 상황에서 모범 사례를 그대로 쓰면 실패한다. **실험 설계로 간다.**

**의사결정 기록**(ADR, Architecture Decision Record)
결정 하나마다 맥락, 고른 것, 버린 것, 그 이유를 한 장에 남긴다.
반년 뒤 "왜 이렇게 했지"를 답하는 유일한 방법이고, 인수인계 비용을 크게 줄인다.

**역산 기획**
결과 시점에서 거꾸로 일정을 짠다. 아마존의 보도자료 먼저 쓰기가 같은 계열이다.
완성 모습을 먼저 문장으로 못 쓰면 아직 기획이 안 된 것이다.

## 하지 말 것

- 방법론 이름을 근거 대신 쓰기. 이름은 절차지 결론이 아니다
- 한 문제에 여러 방법론을 겹쳐 쓰기. 하나로 끝까지 간다
- 복잡한 상황에 명확한 상황용 모범 사례를 적용하기
